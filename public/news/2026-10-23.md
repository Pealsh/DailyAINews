## 【GitHub】anthropics/claude-plugins-official — Anthropic公式のClaude Codeプラグイン配布リポジトリ
**日付**: 観測日 2026-10-23 ｜ **⭐ 総数**: 約43.9k(43,870) ｜ **今日**: 不明(週間 +5,703) ｜ **言語**: Python ｜ **最終更新**: 不明

Anthropicが自ら運営するClaude Code向けプラグインのオフィシャルディレクトリ。リポジトリは`plugins/`(Anthropic社内製)と`external_plugins/`(パートナー・コミュニティ製で審査済み)に分かれ、各プラグインは`.claude-plugin/plugin.json`でメタデータを定義し、任意で`commands/`(スラッシュコマンド)・`agents/`(エージェント定義)・`skills/`(Agent Skill)を同梱する構成になっている。SKILL.mdだけのシンプルなバンドルも`marketplace.json`で`strict: false`を指定すれば取り込めるなど、公式が「雑多な形式」を許容する設計を明示しているのが特徴。週間で5,700超の★増加は、プラグイン/スキルの標準化がエコシステム全体で急速に進んでいることを示す。

### 話題の理由 / 注目度の根拠
GitHub Trending(weekly)でAI関連リポジトリの中でも上位に位置し、Anthropic公式という信頼性の高さから採用判断の基準として参照されやすい。

### 対象読者
Claude Codeでチーム運用のプラグイン/スキルを整備したい開発者、サードパーティプラグインを公開したい開発者。

### 今日試せること
```sh
/plugin install {plugin-name}@claude-plugins-official
```
上記をClaude Code内で実行すると、`plugins/`配下のリストから目的のプラグインを即導入できる。

### 深掘りポイント
`external_plugins/`の審査基準(どこまでが「審査済み」なのか)と、`strict: false`で許容される非標準バンドルの実例をいくつか読むと、自作スキルを配布形式に合わせる際の指針になる。

[リポジトリ](https://github.com/anthropics/claude-plugins-official)

## 【GitHub】cloudflare/security-audit-skill — Cloudflare製・多段階セキュリティ監査Agent Skill
**日付**: 2026-10-23(本日のデイリートレンド) ｜ **⭐ 総数**: 39,355 ｜ **今日**: +2,979 ｜ **言語**: JavaScript ｜ **最終更新**: 不明

CloudflareがClaude Code向けに公開したセキュリティ監査用Agent Skill。README によると、偵察→カバレッジ主導の脆弱性探索→候補の検証→構造化出力(`findings.json`)→独立検証→レポート生成という6フェーズを、それぞれ別のサブエージェントに分離して実行する設計で、Cloudflare社内の脆弱性発見基盤そのものがこの仕組みをベースにしているという。本日のデイリートレンドで★2,979増と急伸しており、「監査結果を機械読み取り可能な形式で、しかも誤検知を自動で削る」という実務的な需要の高さを裏付けている。

### 話題の理由 / 注目度の根拠
本日のGitHub Trending(daily)で★増加数トップクラス。セキュリティベンダー自身が自社基盤を公開した点も信頼性の根拠。

### 対象読者
コードベースの脆弱性を自動洗い出ししたいセキュリティエンジニア、プロダクト開発チーム。

### 今日試せること
```sh
npx skills add https://github.com/cloudflare/security-audit-skill --skill security-audit
```
導入後、Claude Codeに「このコードベースをセキュリティ監査して」と依頼すると6フェーズのパイプラインが起動する。Node.jsと外部ネットワークを遮断したOSサンドボックスが前提なので、実行環境の準備は事前に確認したい。

### 深掘りポイント
「候補検証」と「独立検証」をなぜ分離しているか(誤検知率の低減手法)をREADMEのフェーズ説明から読むと、他の監査系スキルを自作する際のテンプレートになる。

[リポジトリ](https://github.com/cloudflare/security-audit-skill)

## 【GitHub】EveryInc/compound-engineering-plugin — 36スキルで開発ループを自動化するマルチエージェント対応プラグイン
**日付**: 2026-10-23(本日のデイリートレンド、TypeScript部門) ｜ **⭐ 総数**: 25,660 ｜ **今日**: +25 ｜ **言語**: TypeScript ｜ **最終更新**: 不明

EveryInc(Kieran Klaassen・Trevin Chow)が公開した、36個のスキルで構成されるプラグイン。「ブレインストーム→計画→実装→レビュー→学び直しの記録」というループを`/ce-brainstorm`→`/ce-plan`→`/ce-work`→`/ce-simplify-code`→`/ce-code-review`→`/ce-compound`のスラッシュコマンド列で回し、各変更で得た知見を次の変更の計画時に読み込む設計になっている。Claude Code・Cursor・Codex・Grok・Devinなど14種のエージェントホストに対応しており、`/lfg`を使えば一連の作業を自動実行しコミットから(リモートがあれば)PR作成・CI修復ループまで一気通貫でこなす。ただしマージ自体は許可しない限り行わない。

### 話題の理由 / 注目度の根拠
対応ホストの広さ(14種)と、「作業するたびに次が楽になる」ための知見の自動記録という具体的な設計思想が、プラグイン/スキルブームの中で差別化点として注目されている。

### 対象読者
複数のAIコーディングエージェントを併用し、チームでの開発プロセスを標準化したい開発チーム。

### 今日試せること
```sh
/plugin marketplace add EveryInc/compound-engineering-plugin
/plugin install compound-engineering
/ce-brainstorm make background job retries safer
/ce-plan
```
既存ユーザーは`/plugin update`だけでは古いバージョンのままになる点に注意(マーケットプレイスの再取得が必要)。

### 深掘りポイント
`/lfg`の自動PR作成・CI修復ループがどこまで自律的に動くか(マージ判断は人間に残す設計の境界線)を実際に動かして確認すると、自動化の信頼範囲を見極めやすい。

[リポジトリ](https://github.com/EveryInc/compound-engineering-plugin)

- **Hacker News**: `news.ycombinator.com`・`hn.algolia.com`ともにこの実行環境のネットワークポリシーでDNS解決がブロックされ、アクセス不可(接続拒否)。該当媒体の掲載は見送り、件数も記載していない。
- **Reddit**: `reddit.com`も同様にWebFetchからアクセス不可(接続拒否)。r/LocalLLaMA・r/ClaudeAI・r/MachineLearningの直近投稿は確認できなかった。
- **X(Twitter)**: ログイン不要での直接閲覧手段がなく、WebSearch経由でも2026年10月21〜23日付で技術者による具体的な発表・デモ投稿を信頼できる形で特定できなかったため掲載を見送った。
