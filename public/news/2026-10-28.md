## 【GitHub】cloudflare/security-audit-skill — コーディングエージェントを「反証担当者付き」のセキュリティ監査官にするSkill
**日付**: 2026-10-28(週間トレンドで確認) ｜ **⭐ 総数**: 50,062 ｜ **今日**: 不明(週間 +16,593) ｜ **言語**: 不明(Markdown中心、検証スクリプトは`.cjs`) ｜ **最終更新**: 不明

Cloudflare製、MITライセンス。コーディングエージェントにセキュリティ監査を任せるためのSkillで、(1)アーキテクチャ・信頼境界・入力経路を`architecture.md`と`coverage-ledger.json`にマッピングする偵察、(2)網羅表の未調査領域から孤立したハンター役エージェントを割り当てて調査するハンティング、(3)見つかった候補ごとに「発見者とは別のエージェント」が反証を試みる候補検証、(4)`confirmed`/`needs_validation`/`rejected`に分けて`findings.json`へ構造化出力、(5)最終的な記録を別のエージェントが再検証、(6)対象に依存しない形で`REPORT.md`等を生成する報告、という6フェーズで構成される。これはCloudflare自身のブログ記事「Build your own vulnerability harness」で紹介された、同社の大規模な脆弱性発見ハーネスの出発点となった単一リポジトリ版だという。同じリポジトリに対して複数回実行すると、過去のledgerとfindingsを使って未調査の差分だけを追い直す設計になっている。

### 話題の理由 / 注目度の根拠
今回調査した中で週間の増加数が最大(+16,593)。大手インフラ企業であるCloudflareが、自社の脆弱性発見ハーネスの「種」となったツールをそのまま公開し、かつその経緯をブログ記事という一次情報で裏付けている点が、個人・小規模チーム製のSkillが多い中で際立っている。

### 対象読者
自社コードベースやOSS依存先の脆弱性を、人力レビューの前に一次スクリーニングしたいセキュリティチーム・プラットフォームエンジニア。

### 今日試せること
```sh
# Skills CLI経由でインストール
npx skills add https://github.com/cloudflare/security-audit-skill \
  --skill security-audit --global

# 対応エージェントに自然文で依頼するだけで発火する
# 例: "security audit this codebase" / "find security vulnerabilities in ./src"
```
必要環境として、並列サブエージェントをサポートするモデル、Node.js(検証スクリプト用)、そして外部ネットワークを遮断したOSレベルのサンドボックスが明記されている。サンドボックスが無い場合、ビルド/テスト/実行を伴う確認はスキップされ`needs_validation`止まりになる設計。

### 深掘りポイント
README内の設計原則に「Defense-in-depth gaps are not vulnerabilities(多層防御の欠落そのものは脆弱性ではない)」とあり、チェックリスト型の脆弱性診断と「実害の有無」で判定するこのSkillの違いが分かる。「単独実行では複数回実行の約半分しか脆弱性を見つけられなかった」という自社テスト結果も明記されており、1回実行で終わらせない運用設計の参考になる。

### 話題の理由 / 注目度の根拠
本日のGitHub Trending(daily)で+2,859。コーディングエージェントが作るUIが「いかにもAI生成っぽい」という具体的な不満に対して、抽象的なガイドラインではなく実ブラウザでのリンティングスクリプトと別コンテキストレビューという検証可能な仕組みで応えている点が評価されている。
