## 【GitHub】Leonxlnx/taste-skill — 247サイト調査由来の美的方向性と実ブラウザ確認で「ありきたりなランディングページ」を防ぐSkill

### 話題の理由 / 注目度の根拠
週間トレンドで+4,359。「エージェントに実ブラウザで自分の出力を見せて自己採点させる」という検証ループを、デザインの美的判断という定量化しにくい領域に持ち込んだ設計が評価されている。

### 対象読者
コーディングエージェントにランディングページやダッシュボードのUIを一から作らせたいが、毎回似たようなテンプレート的な見た目になることに不満がある開発者・個人開発者。

```sh
/plugin marketplace add Leonxlnx/taste-skill
/plugin install taste-skill@taste-skill
```
Node 22以降とChrome/Edge/Chromiumのいずれかが必要。API キーは不要だが、画像検索時のみネットワーク接続が要る。

## 【GitHub】CopilotKit/OpenBot — AG-UI準拠なら任意のフレームワークのエージェントを「ガバナンス付きBot」として動かすセルフホスト型テンプレート
**日付**: 2026-10-31(本日のデイリートレンドで確認) ｜ **⭐ 総数**: 8,729 ｜ **今日**: +707 ｜ **言語**: TypeScript ｜ **最終更新**: 不明

CopilotKitが公開したベータ版のMITテンプレート。README自身が「プロダクトではなくテンプレート」と明言しており、クローンして自社向けに作り変えることを前提とする。各「Bot」は専用のブラウザ(ログイン情報含む)・ファイル領域・付与されたツールのみを持ち、すべてのブラウザ・ファイル・シェル操作はサーバー側ゲートウェイを必ず経由する。ゲートウェイはCEL式で記述されたポリシーを評価し(拒否が許可より先に評価され、ポリシー未設定や壊れたルールは拒否扱いというフェイルクローズ設計)、監査ログを書き込んだ上で初めて操作を実行する。AG-UIのエンドポイントであればLangGraph・Mastra・CrewAI・Pydantic AI・Google ADKなど任意のフレームワークのエージェントをBotとして差し替えられ、ガバナンスはフレームワークに依存せずプロトコル側で一貫して適用される。初期状態では「General Assistant」「Knowledge」があり、`examples/fintech/catalog/`には経費申請確認やリリースノート作成など業務特化のBot例が10種類用意されている。

### 話題の理由 / 注目度の根拠
本日のデイリートレンドで+707。「AIコワーカーにブラウザやファイルへのフルアクセスを与える」という、権限委譲が避けられないテーマに対し、CEL式ポリシー・監査ログ・フェイルクローズという具体的なガバナンス機構をフレームワーク非依存の形で示した点が注目されている。

### 対象読者
社内の定型業務(経費処理・議事録フォローアップ・リリースノート作成など)をエージェントに任せたいが、操作ログと権限制御を必須としたい企業の情報システム担当・プラットフォームエンジニア。

### 今日試せること
```sh
git clone https://github.com/CopilotKit/OpenBot.git
cd OpenBot
cp .env.example .env
bun install
npx --yes copilotkit@latest login
bash scripts/start.sh
```
起動後`http://localhost:3010`を開いて初期Botと対話できる。Docker・Bun 1.4以上・CopilotKit Intelligenceの無料プロジェクト・モデルAPIキー(例: OpenAI)が前提。

### 深掘りポイント
`.env.example`の`OPENBOT_SINGLE_USER=true`は全員を単一管理者として扱う検証用設定であり、他者にアクセスさせる前にGoogle/Microsoft/Oktaいずれかのサインイン設定とこの行の削除、本番運用時のTLS前段設置が必須とREADMEが明記している。この前提を読まずに社内展開すると権限分離が機能しない点は要注意。

[リポジトリ](https://github.com/CopilotKit/OpenBot)

## 【GitHub】lightpanda-io/browser — Zigで新規実装されたAIエージェント向けヘッドレスブラウザ。Chrome比で大幅な軽量・高速化を主張
**日付**: 2026-10-31(本日のデイリートレンドで確認) ｜ **⭐ 総数**: 38,286 ｜ **今日**: +559 ｜ **言語**: Zig ｜ **最終更新**: 不明

Chromiumのフォークでも WebKit のパッチでもなく、Zigで一から実装されたヘッドレスブラウザ。描画エンジンを持たず、JavaScript実行とDOM操作に特化している点が特徴で、HTTPローダー(libcurl)・HTMLパーサー(html5ever)・JavaScriptエンジン(V8)を組み合わせ、DOM API・XHR/Fetch・Ajax・Cookie・プロキシ・広告ブロック・`robots.txt`遵守に対応する。プロジェクト自身の計測(AWS EC2 m5.large、実ウェブページ933件)では、100ページ処理時のピークメモリがHeadless Chromeの2GBに対しLightpandaは123MB(約1/16)、実行時間はChromeの46秒に対し5秒(約9倍速い)と主張している。CDPおよびWebDriver BiDiのサーバーとして動作しPuppeteer等から接続できるほか、`agent`サブコマンドではOpenAI/Anthropic/Gemini/OpenRouter/Ollama等を使った自然言語でのブラウザ操作が可能で、操作ログを`/save`でPandaScript(JavaScript形式)として書き出し、LLMなしで`lightpanda run`により再生できる。stdio/HTTPのMCPサーバーとしても組み込める。

### 話題の理由 / 注目度の根拠
本日のデイリートレンドで+559。エージェントによるブラウザ操作が数百〜数千インスタンス規模で動く時代に、Chromium系ヘッドレスブラウザのメモリ・CPU消費がボトルネックになりやすいという実務課題に対し、新規実装で大幅な軽量化を主張している点が評価されている。

### 対象読者
多数のブラウザインスタンスを並行稼働させてWebスクレイピングやAIエージェントのブラウジングを行っている開発者・インフラ担当。既存のPuppeteer/Playwrightスクリプトの置き換え先を探しているチーム。

### 今日試せること
```sh
./lightpanda fetch --obey-robots --dump html https://example.com
./lightpanda serve --host 127.0.0.1 --port 9222   # Puppeteer等からCDP接続
./lightpanda agent --task "ニュースサイトの見出しを3件要約して"
```
Dockerイメージ`lightpanda/browser:latest`でポート9222のCDPサーバーをすぐ起動することも可能。

### 深掘りポイント
LinuxバイナリはglibcベースのためAlpineなどmusl系では動作せず、Androidネイティブビルドもなく、WindowsはWSL2経由が前提という制約がある。自社ベンチマークの数値は条件により変わり得るため、実際のワークロードで再計測する価値がある。`LIGHTPANDA_DISABLE_TELEMETRY`でテレメトリを無効化できる点も導入時に確認したい。

[リポジトリ](https://github.com/lightpanda-io/browser)
