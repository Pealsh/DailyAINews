## 【GitHub】thedotmack/claude-mem — Claude Codeにセッションを超えた「記憶」を持たせるプラグイン
**日付**: 2026-11-02時点でトレンド確認 ｜ **⭐ 総数**: 約11万(GitHub表示の概数。参照時点により4万台〜11万台まで複数の報告があり、急成長中のため確定値は不明) ｜ **今日**: +1,799 ｜ **言語**: TypeScript ｜ **最終更新**: 2026-11-02

claude-memは、Claude Code・Codex・Gemini CLI・OpenCodeなどのAIコーディングエージェントに永続的なメモリを与えるプラグイン。セッション中のツール利用(ファイル編集、コマンド実行など)を記録し、AIによる要約を生成してローカルのSQLite(FTS5全文検索)とChromaベクトルストアに保存する。新しいセッションが始まると、キーワード検索とベクトル検索を組み合わせたハイブリッド検索で関連する過去の文脈だけを呼び出し、全履歴を毎回読み込むより大幅にトークンを節約すると説明されている。`search`や`timeline`などのMCPツールを4つ提供し、SessionStart/PreToolUse/Stopなどのフックで自動的に記録・注入が行われる。`<private>`タグで記録対象から除外する機能もある。

### 話題の理由 / 注目度の根拠
日間トレンド2位で+1,799★。「エージェントは毎回ゼロから始まる」という長年の不満に対する実用的な解決策で、Claude Code公式プラグインマーケットプレイス経由で簡単に導入できる点が広く試されている理由と見られる。

### 対象読者
Claude Code・Codex・Gemini CLIなどを日常的に使い、プロジェクトの背景知識をエージェントに何度も説明し直すのに疲れている開発者。

### 今日試せること
```sh
# Claude Code内で実行
/plugin marketplace add thedotmack/claude-mem
/plugin install claude-mem
# または
npx claude-mem install
```
インストール後、`localhost:37777`のWebビューアで記録されたメモリを閲覧できる。

### 深掘りポイント
`CLAUDE_MEM_MODE`で出力言語を切り替えられる点や、FTS5とベクトル検索を組み合わせたハイブリッド検索の設計、どの情報を要約時に残し何を捨てるかの基準をREADME・ソースコードで確認すると、他の記憶システムとの比較軸が見えてくる。

[リポジトリ](https://github.com/thedotmack/claude-mem)

## 【GitHub】vercel-labs/agent-desktop — アクセシビリティAPIでAIにデスクトップ操作をさせるCLI
**日付**: 2026-11-02時点でトレンド確認 ｜ **⭐ 総数**: 不明(GitHub API直接参照不可のため未確認) ｜ **今日**: +2,243(日間トレンド1位) ｜ **言語**: Rust ｜ **最終更新**: 2026-11-02

agent-desktopは、AIエージェントにmacOS/Windows/Linux上の実際のデスクトップアプリケーションを操作させるApache-2.0ライセンスのCLIとCライブラリ。スクリーンショットを見て座標をクリックする「視覚ベース」の手法ではなく、OSのアクセシビリティツリーを使う点が特徴で、`snapshot`コマンドで画面内の操作可能なUI要素をJSON形式(各要素に`ref`付き)で取得し、エージェントは`ref`を指定して`click`などの操作を行い、再度`snapshot`して結果を確認する。参照先が古くなっている場合は`STALE_REF`などの明示的なエラーを返し、誤操作を防ぐ設計。約56個の操作コマンド(観察・クリック/キーボード操作・ウィンドウ制御・クリップボード・通知など)を備え、デフォルトはヘッドレス動作(カーソルを動かさない)で、`--headed`指定時のみ画面上で実際にカーソルが動く。密集したUIには`snapshot --skeleton`で概観を取り、`--root`で特定領域を絞り込む運用が想定されている。

### 話題の理由 / 注目度の根拠
本日の日間トレンド1位(+2,243★)。「ブラウザだけでなく実際のデスクトップアプリをAIに触らせたい」という需要に対し、座標クリック方式より壊れにくいアクセシビリティAPIベースで応えた点が支持されていると見られる。

### 対象読者
ブラウザ操作の自動化(computer use)だけでは対応できない、ネイティブのデスクトップアプリ(業務システム、レガシーソフトなど)をAIエージェントに操作させたい開発者。

### 今日試せること
```sh
npm install -g agent-desktop
# macOSはアクセシビリティ権限の許可が必要、Linuxはat-spi2-coreが必要
agent-desktop snapshot
```

### 深掘りポイント
`libagent_desktop_ffi`を使えば他言語から直接呼び出せる設計になっている点、`--window-id`による複数ウィンドウの明示的な区別、READMEが明記する「スナップショットやクリップボード経由で個人情報が露出しうる」というプライバシー上の注意点を確認しておきたい。

[リポジトリ](https://github.com/vercel-labs/agent-desktop)

### 話題の理由 / 注目度の根拠

## 【GitHub】cloudflare/security-audit-skill — Cloudflare社内の脆弱性発見ツールを公開したセキュリティ監査Skill
**日付**: 2026-11-02時点で週間トレンド確認 ｜ **⭐ 総数**: 約5.7万(GitHub表示の概数。公開から時間が経つにつれ1.7万→3.3万→4.3万→5.7万と報告時点ごとに増加) ｜ **今日**: 不明(週間+10,069) ｜ **言語**: JavaScript ｜ **最終更新**: 2026-09-14

security-audit-skillは、Claude CodeやCodexなどのコーディングエージェントを構造化されたセキュリティ監査官に変えるSkill。READMEによれば、これはCloudflare社内の脆弱性発見ハーネスの元になった種コード。6段階のパイプラインで動作する: ①偵察(アーキテクチャと信頼境界をマッピングし`architecture.md`と`coverage-ledger.json`を作成)、②カバレッジ主導のハンティング(担当範囲ごとにハンター役エージェントを割り当て、クリティック役がヌケを探す)、③候補の検証(発見者とは別のエージェントが反証を試みる)、④構造化出力(confirmed/needs_validation/rejectedに分類した`findings.json`)、⑤独立した再検証、⑥レポート出力。発見者と検証者を分離する設計と、「チェックリスト違反」ではなく「実証された影響」で深刻度を判断する方針が特徴。対象コードを安全に実行するOSレベルのサンドボックスが無いと、発見事項は未確認のままになるとも明記されている。

### 話題の理由 / 注目度の根拠
週間+10,069★。大手クラウド企業が自社の実運用ツールの出発点をそのまま公開した点、発見者と検証者を分ける仕組みがAIによる誤検知・過剰報告を抑える工夫として注目されていると見られる。

### 対象読者
AIコーディングエージェントによるコードレビューを導入したいセキュリティ担当者・開発者。特に自前のコードベースに対して定期的な脆弱性スキャンの第一段階を自動化したい層。

### 今日試せること
```sh
npx skills add https://github.com/cloudflare/security-audit-skill --skill security-audit
# Claude Code / Codexなどの対応エージェント内で
# 「このコードベースをセキュリティ監査して」と指示すると起動
```
結果は既定で`~/security-audit-skill/<repo-name>/run-<N>`に出力される。

### 深掘りポイント
「1回の実行で全脆弱性の半分程度しか見つからない」とCloudflare自身が認めている点、つまり複数回実行を前提にした設計思想や、メモリ安全性・LLM固有の脆弱性・サプライチェーンなど分野別の参考資料がどう構成されているかを読むと、AIによる監査の限界と使い方の勘所がわかる。

[リポジトリ](https://github.com/cloudflare/security-audit-skill)

## 【GitHub】max-sixty/worktrunk — 複数AIエージェントを並行動作させるgit worktree CLI
**日付**: 2026-11-02時点で日間トレンド確認 ｜ **⭐ 総数**: 不明(参照元により数百〜1万以上まで差があり確定できず) ｜ **今日**: +136 ｜ **言語**: Rust ｜ **最終更新**: 2026-11-02

worktrunk(コマンド名`wt`)は、同じリポジトリ上で複数のAIコーディングエージェントを並行して動かす際の作業ディレクトリの衝突を避けるための、git worktree管理CLI。素のgit worktreeは`git worktree add`と`cd`でブランチ名を二度書く必要があるなど扱いにくいが、worktrunkはブランチ名だけで対象のworktreeを指定でき、パスは設定可能なテンプレートから自動生成される。主なコマンドは`wt switch`(worktreeへ移動、無ければ作成)、`wt list`(ahead/behind数やCIステータス、AIが生成したブランチ概要を表示)、`wt merge`、`wt remove`。`wt switch -c -x claude feat`のように、ブランチ+worktreeの作成とClaude Codeの起動を一度に行うこともできる。作成・マージなどのイベントにフックをかけられる他、LLMによるコミットメッセージ生成、PRを`wt switch pr:123`でチェックアウトする機能、APFS/btrfs/XFSのcopy-on-writeを使ってworktree間でビルドキャッシュ(`target/`や`node_modules/`)を共有する機能も持つ。

### 話題の理由 / 注目度の根拠
日間+136★とまだ規模は小さいが、「複数のAIエージェントを同じリポジトリで同時に走らせる」という最近よく聞かれる運用パターンに特化したツールとして日間トレンドに入った点が注目点。

### 対象読者
Claude CodeやCodexなど複数のコーディングエージェントを同じプロジェクトで並行に走らせ、worktreeの管理やビルドキャッシュの重複に悩んでいる開発者。

### 今日試せること
```sh
brew install worktrunk   # Homebrew
# または cargo install worktrunk
wt switch -c -x claude feature-branch
wt list --full
```
ディレクトリ移動を伴うためシェル統合の設定が必要。

### 深掘りポイント
`hash_port`というテンプレートフィルタでworktreeごとに決定的なポート番号を割り振る仕組みや、ビルドキャッシュ共有がどのファイルシステムのcopy-on-write機能に依存しているかを確認すると、並行開発環境の設計として応用しやすい。

[リポジトリ](https://github.com/max-sixty/worktrunk)

## 【AI機能】Agent SkillsがLinux Foundation傘下Agentic AI Foundationへ移管
**日付**: 2026-10-22発表

Anthropicは、2025年10月にClaude Codeの機能として始まったAgent Skills標準を、Linux Foundation傘下の新団体Agentic AI Foundation(AAIF)に寄贈した。移管対象はAgent Skillsという名称・ロゴ・GitHub organization(agentskills/agentskills)・仕様書を公開しているagentskills.ioドメインの4点。Anthropic発表の数値として、これまでに約100万件のSkillが公開され、インストール数は約2.8億件に達したとされる(自社発表であり第三者検証はされていない)。SKILL.mdのフォーマット自体は変更されず既存Skillはそのまま動くとされるが、Claude Code専用のフロントマター項目をclaude.aiやSkills APIにアップロードするとエラーになる場合があるとの指摘もある。同日、OpenAIのOpen Responses、Hugging FaceのOpenEnv、AlibabaのOpenSandboxも同財団に加わっており、AAIFはすでにAnthropicのMCP(Model Context Protocol)も管轄している。

### 話題の理由 / 注目度の根拠
一企業(Anthropic)の独自機能として始まったものが、70以上のエージェント基盤に統合されたのちベンダーニュートラルな標準化団体に移管された、という「エコシステムの中立化」の動きとして注目されている。

### 対象読者
Agent Skillsを自社プロダクトやツールに組み込んでいる、あるいは組み込みを検討している開発者・プラットフォーム提供者。

### 今日試せること
既存のSKILL.mdベースのSkillはそのまま動作するはずだが、claude.ai/Skills API以外の環境にアップロードする前に、Claude Code専用のフロントマター項目が含まれていないか確認しておくと安全。

### 深掘りポイント
仕様書本体(agentskills.io)の最新版と、AAIFの統治構造(誰が仕様変更を承認するか)を確認すると、今後Anthropic以外の企業がAgent Skillsにどう関与していくかが見えてくる。

## 【AI機能】GitHub Copilot Fusion — タスクごとに最適なモデルを自動選択するルーティング機能がGA
**日付**: 2026-10-28(米国時間、日本時間10/29)、GitHub Universe 2026にて発表

GitHub Copilot Fusionは、コーディングタスクの各ステップに対して使用するAIモデル(または複数モデルの組み合わせ)を自動的に選び分けるルーティング機能で、2026年9月4日のリサーチプレビュー「Project HydraFusion」から昇格し一般提供が開始された。複数の報道で数値は食い違うものの、GitHubは「タスクあたりのAPIコストを平均半分程度に削減しつつ、トークン使用量も半減、処理時間も約40%短縮」とし、Microsoft CoreAI担当のSatya Nadellaは「40%高速・最大77%低コスト」という異なる数値を挙げている(いずれもGitHub側発表の数値で第三者検証はされていない)。同時に、GitHub Copilotアプリ、複数エージェントで動く「Copilot Projects」、より深いコードレビュー機能も発表された。

### 話題の理由 / 注目度の根拠
GitHub Universe 2026の主要発表の一つで、「最適なモデルを毎回人間が選ぶ」のではなく基盤側が自動化する方向性を大手ベンダーが示した点が注目されている。コスト・速度の具体的な改善幅を主張している点も関心を集めている。

### 対象読者
GitHub Copilotを業務で使っており、モデル選択やコストの最適化に関心がある開発者・エンジニアリングマネージャー。

### 今日試せること
GitHub Copilotの対応プランでFusionの有効化状況を確認し、既存ワークフローと比較してコスト・速度の変化を実際に計測してみる(2026年11月30日までモデル利用コストが有料プランで割引されるとの報道もあるため、期間限定の条件は要確認)。

### 深掘りポイント
「平均半分のコスト」という主張の算出根拠(どのタスク種別・モデル組み合わせで測ったか)が公開情報だけでは明確でないため、自分の実ワークロードで同様の比較を行い、報道の数値とどの程度一致するか検証する価値がある。

## 取材メモ
- GitHub Trendingは`https://github.com/trending`のdaily/weeklyページと各リポジトリのREADME・GitHub API/ページを直接参照して作成。ただしこのセッションのGitHub REST API(MCP経由)は個別リポジトリ照会を拒否したため、総スター数の多くはGitHubページ表示の概数(3桁有効数字程度)に基づき、厳密な整数値は「不明」としている。複数の第三者記事(異なる時点のスナップショット)でスター数の報告に差があるリポジトリ(claude-mem、security-audit-skill、hallmark、worktrunk)は、本稿では直近時点の数値を概数として採用し、差異がある旨を明記した。
- Hacker News(hn.algolia.com)、Reddit(reddit.com/old.reddit.com/api.reddit.com)、Simon Willisonのブログ(simonwillison.net)、ニュースレター各サイト(tldr.tech、bensbites.com、therundown.ai)は、このクラウドセッションのネットワークポリシーにより直接アクセスができず(プロキシが403で接続拒否、またはDNS解決不可)、本稿ではこれら媒体からの項目掲載を見送った。代替としてWebSearchでの間接調査を試みたが、具体的な記事タイトル・日付・エンゲージメント数値について複数の矛盾や未確認点(例: Ben's Bites「AI is overwhelming and I'm doing it wrong」、Simon Willisonの「datasette-llm 0.1a9」、The Rundown AIの特定号など)が見つかり、独自検証で実在を確認できなかったため、事実として書かずに全て不採用とした。
- X.com(x.com)も同様にDNS解決不可で直接アクセスできず、間接調査で得られた個別ツイートのURL・エンゲージメント数(いいね数等)は検証不能だったため掲載を見送った。GitHub Copilot Fusionについては、X上の反応ではなく複数の独立した報道記事(thenextweb.com、itwire.com等)で事実関係を確認できたため、【AI機能】として掲載した。
- 上記の事情により、本稿は【GitHub】5件と【AI機能】2件で構成している。数値を「不明」と記載した箇所は、API/サイトへの直接アクセスができず確認できなかったことを意味し、推定や代入は行っていない。
