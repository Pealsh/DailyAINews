## 【GitHub】Donchitos/Claude-Code-Game-Studios — Claude Codeを「ゲームスタジオ」化する49エージェント・74Skillのテンプレート
**日付**: 2026-11-04時点でデイリートレンド13位として確認 ｜ **⭐ 総数**: 約34,579(GitHub Trendingページ表示の概数) ｜ **今日**: +1,181 ｜ **言語**: Shell ｜ **最終更新**: 2026-11-03/04

Claude-Code-Game-Studiosは、Claude Codeのセッションをゲームスタジオのワークフローそのものに変えるテンプレートリポジトリ。ディレクター・部門リーダー・専門スタッフ役を担う49種のサブエージェント、74個のスラッシュコマンドSkill、15個のフック、14個のパス限定ルール、62個の文書テンプレートが同梱され、Godot 4・Unity・Unreal 5それぞれ専用のエージェントセットも用意されている。エージェントは「質問→選択肢の提示→ドラフト作成→承認待ち」という協調プロトコルに従って動くよう設計されている。README内では`modes.rigor`(minimal/standard/full)という設定が導入されており、重厚なstandardモードが実際のゲーム開発より前に30個もの文書を生成してしまい、レビュアー評価が最下位になったという反省からデフォルトはminimalに設定されている。

### 話題の理由 / 注目度の根拠
GitHubデイリートレンド13位、当日+1,181★。「Claude Codeを使った多エージェント・オーケストレーション・テンプレート」という人気ジャンルへの新規参入として伸びている。

### 対象読者
Claude Codeでインディー・小規模チームのゲーム開発を行い、アドホックなプロンプトではなくスタジオ的な構造化ワークフローを試したい開発者。

### 今日試せること
```sh
git clone https://github.com/Donchitos/Claude-Code-Game-Studios.git my-game
cd my-game && claude
# Claude Code内で
/setup-engine godot 4.7
```

### 深掘りポイント
`modes.rigor`の設計と、過剰工程を防ぐためのエージェント階層・フックによる検証ロジックを読んでみると良い。

[リポジトリ](https://github.com/Donchitos/Claude-Code-Game-Studios)

## 【GitHub】spotify/portal-ai-plugins — Spotifyが社内開発者ポータルをAIコーディングエージェントに接続する公式プラグイン
**日付**: 2026-11-04時点でデイリートレンド7位として確認 ｜ **⭐ 総数**: 約3,013(GitHub Trendingページ表示の概数) ｜ **今日**: +94 ｜ **言語**: TypeScript ｜ **最終更新**: 2026-11-03頃

portal-ai-pluginsは、Spotifyが自社の内部開発者ポータル「Portal」をClaude Code・Codex・Cursor・piなどのAIコーディングエージェントに接続するための公式プラグイン集。内部CLIの`@spotify/portal-cli`をラップし、エージェントがサービスカタログの検索、サービス/オーナーシップの健全性サマリー取得、Portal上のアクション実行、「Fleetshift」という移行作業(作成・実行・状況確認・トラブルシュート・PR作成)をIDEから離れずに行えるようにする。オプションの「shunt」プラグインでは、一括読み取りやボイラープレート生成といった作業をコストの低いワーカーモデルにPortal経由で振り分けるコストルーティングの仕組みも用意されている。大企業が社内ツールとAIエージェントの橋渡しをオープンソースで公開した事例として注目される。

### 話題の理由 / 注目度の根拠
GitHubデイリートレンド7位。大手テック企業が社内開発者ポータルをAIエージェント向けにオープンソース化した事例として、「エージェント連携は自社ツールにも来る」という流れを象徴している。

### 対象読者
社内開発者ポータル(Backstageなど)を運用、または導入検討しているプラットフォームエンジニア/インフラチーム。

### 今日試せること
```sh
claude plugin marketplace add spotify/portal-ai-plugins
claude plugin install portal@portal
# 新しいセッションで
/portal:setup
```

### 深掘りポイント
「shunt」プラグインによる、安価なワーカーモデルへのコストルーティングのパターンは、他の社内ツール連携にも応用できる設計。

[リポジトリ](https://github.com/spotify/portal-ai-plugins)

## 【GitHub】JetBrains/thinkrail — piエージェントを包んだJetBrainsのオープンソース・エージェンティックIDE
**日付**: 2026-11-04時点で週間トレンド7位として確認(公開報道は2026-10-24前後) ｜ **⭐ 総数**: 約7,395(GitHub Trendingページ表示の概数) ｜ **今週**: +4,812 ｜ **言語**: TypeScript ｜ **最終更新**: 直近(複数メディアが10/24〜10/31に報道)

ThinkRailは、JetBrainsのInnovationHub発・Apache 2.0ライセンスのオープンソース・エージェンティックIDE。コーディングエージェント「pi」を、Monacoエディタ・ファイルツリー・ターミナル・差分レビューコメント機能を備えたフルのワークベンチで包んでおり、タスクごとにgit worktreeで隔離された作業スペースを作成できる。1つのワークスペース内で、それぞれ独自のモデル選択とコスト表示を持つ複数のpiチャットセッション(サブエージェント込み)を並行実行でき、エージェントが読み書きする「SPEC.md」という生きた仕様書グラフも持つ。他のコーディングエージェント向けに作られたAgent SkillsやMCPサーバー(承認プロンプトつき)も再利用できる設計になっている。

### 話題の理由 / 注目度の根拠
週間トレンド7位、週間+4,812★。JetBrainsのような大手IDEベンダーが、git worktreeベースのマルチセッション並行実行を前面に出したエージェンティックIDEに参入したことは、Claude Code/Cursor的なツールへの対抗シグナルとして注目されている。

### 対象読者
CLI中心ではなくGUIベースのエージェンティック開発環境を求め、マルチワークスペース・マルチモデルの並行作業をネイティブに使いたい開発者。

### 今日試せること
デスクトップアプリまたは`thinkrail` CLIをインストールし、`thinkrail ~/code/my-repo`で既存リポジトリを開いてワークスペースを作成する。

### 深掘りポイント
Claude Code向けに書かれたAgent SkillsがpiやThinkRail上でどこまで「そのまま動く」のか、MCP/Skill再利用層の互換性を検証してみる価値がある。

[リポジトリ](https://github.com/JetBrains/thinkrail)

## 【GitHub】AgriciDaniel/claude-seo — 26Skill・19エージェントでSEO監査を自動化、AI検索(GEO)対応も診断
**日付**: 2026-11-04時点で週間トレンド6位として確認 ｜ **⭐ 総数**: 約26,294(GitHub Trendingページ表示の概数) ｜ **今週**: +4,091 ｜ **言語**: Python ｜ **最終更新**: 直近

claude-seoは、MITライセンスで公開されているClaude Code向けのSEO監査プラグイン。26個のサブSkillと最大17並列で動く19種の専門エージェントが、テクニカルSEO、E-E-A-T/コンテンツ品質、スキーマ(構造化データ)、AI検索時代に向けた「GEO(Generative Engine Optimization)」対応度、ローカル/マップSEO、バックリンク、画像生成、ドリフト監視、ECサイト特有の観点までを分担してカバーする。判断の難しい5つのエージェントはOpusモデル、それ以外はSonnetモデルで動く設計。READMEにはスラッシュコマンドの実行例と、採点付きの監査レポートのサンプル出力が示されている。

### 話題の理由 / 注目度の根拠
週間+4,091★はSEOというニッチな用途のツールとしては大きな伸びで、AI検索エンジンから引用されやすいかを測る「GEO」という新しいSEO観点を扱っている点が目新しい。

### 対象読者
自社サイトのSEO/AI検索対応を、別のSaaSダッシュボードではなくコーディングエージェント上で継続的・自動的に監査したい開発者やマーケター。

### 今日試せること
```sh
# Claude Code内で
/seo setup
/seo audit https://example.com
/seo geo https://example.com   # AI検索での引用されやすさを診断
```

### 深掘りポイント
「GEO」と「エージェント対応度」監査カテゴリの評価基準を読んでみると、従来のSEOとLLM時代のSEOの違いが具体的に分かる。

[リポジトリ](https://github.com/AgriciDaniel/claude-seo)
