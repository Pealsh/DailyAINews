## 【GitHub】NVIDIA/auto-ontology — 企業データに「認定済みの意味」を与えてAIエージェントのSQL生成を正確にするフレームワーク
**日付**: 2026-11-05時点でトレンド確認 ｜ **⭐ 総数**: 約4.8k ｜ **今日**: +2,053(日間トレンド上位) ｜ **言語**: Python(バックエンドFastAPI)+TypeScript(フロントNext.js) ｜ **最終更新**: 不明

auto-ontologyは、NVIDIAが公開したApache-2.0ライセンスのオープンソースフレームワークで、企業のデータベーススキーマや業務文書から用語・SQL定義・テーブル間の結合関係を抽出し、Postgres+pgvectorベースの「意味グラフ(セマンティックレイヤー)」を自動生成する。生成された内容は業務の専門家が人手で検証・認定(certify)する前提で、クエリ実行時はエージェントが質問の意図を分類し、埋め込み検索で該当する認定済み用語を取得、SQLを生成・検証してから、どの定義に基づいた回答かという根拠(provenance)つきで回答する。Databricks・Postgres・Snowflake・DuckDBなど複数のデータソースに対応し、MCPサーバー・CLI・REST APIの形でCursorやClaude Desktopなどから利用できる。NVIDIA NIM Nemotronモデルを既定としつつ、OpenAI互換の任意のエンドポイントも使える。NVIDIAは自社検証で「オントロジー作成の時間を90%削減した」としている(第三者未検証の自社発表値)。

### 話題の理由 / 注目度の根拠
GitHub日間トレンドでAI関連として最大の伸び(+2,053★)。NVIDIAがGTCベルリンで発表した「Agent Knowledge Foundation」構想の一部として位置づけられており、「エージェントが列名から意味を推測する」のではなく人間が認定した定義に基づかせるという、エージェント型BI/分析の信頼性問題に直接答える内容であることが支持の背景と見られる。

### 対象読者
社内データベースに対してAIエージェントで分析・質問応答をさせたいが、誤ったSQLや列の取り違えによる誤答を懸念しているデータ・分析エンジニア。

### 今日試せること
```sh
git clone https://github.com/NVIDIA/auto-ontology.git
cd auto-ontology
cp .env.example .env
docker compose up -d --build
# ~/.cursor/mcp.json 等からMCPサーバー(http://localhost:3003/mcp)に接続
```

### 深掘りポイント
「90%削減」というNVIDIA自社発表値の算出根拠(どのデータセット・比較対象か)が公開情報だけでは明確でない点、人間による「認定」フローが実際にどこまで厳密か(誰が承認権限を持つか)をREADMEで確認する価値がある。

[リポジトリ](https://github.com/NVIDIA/auto-ontology)

本日の日間トレンドで+1,376★。著者の知名度(TypeScript教育者としての大きなフォロワー基盤)に加え、「フレームワークに支配されず部分的に使える」という設計思想が、Spec-Kit的な重量級フレームワークへの反動として支持されていると見られる。なお総スター数は媒体によって7万台から24万台まで報告が分かれており、本稿のGitHub直接参照時点の数値(313.2k)も含め急変動中とみられ確定値としては扱わない。

## 【AI機能】Claude Code v2.1.317 / v2.1.318 — メール送信前の確認機能とコスト可視化APIを追加
**日付**: v2.1.317は2026-11-03、v2.1.318は2026-11-04公開(GitHub Releasesで確認)

Claude Codeの直近2リリースでは、エージェントが外部ネットワークに情報を送る挙動に対する安全機能とコスト管理機能が強化された。v2.1.317では、WebやShellツール呼び出しがユーザーのアカウントのメールアドレスをネットワークに送信しようとする際に確認を求める機能、Agent SDKのフックコールバックで`onFailure: "block"`を指定できる機能、組織単位のコストレポートを取得するゲートウェイ管理APIエンドポイント(`GET /v1/organizations/analytics/cost`)が追加された。v2.1.318では、`mantle`アップストリーム向けにAWSのクロスアカウントロール・開発者単位のコスト帰属を行う`assume_role`設定、モデルのfork機能への`effort`オプション指定、`claude auth status`でのログイン期限表示とログイン失効10日前の警告が追加されている。

### 話題の理由 / 注目度の根拠
AIコーディングエージェントが自律的にWebやShellツールを使う機会が増える中、個人情報(メールアドレス)が意図せず外部に送信されるリスクに対し、確認ステップを挟むという具体的な安全策を講じた点、また組織運用での「誰が・どのタスクで・どれだけコストを使ったか」を可視化する機能が同時に強化された点が実務上の関心を集めている。

### 対象読者
Claude Codeを組織・チームで運用し、コスト管理やエージェントの安全なツール利用に関心があるエンジニアリングマネージャー・プラットフォームチーム。

### 今日試せること
```sh
claude --version   # 2.1.318以上になっているか確認
claude auth status # ログイン期限の表示を確認
```
Web/Shellツールを使うワークフローで、メールアドレス送信時に確認ダイアログが出る挙動を実際に確認してみる。

### 深掘りポイント
「メールアドレス送信前の確認」がどのツール呼び出し(WebFetch/Bash等)まで網羅しているか、ゲートウェイのコストAPIがSSO/OIDCのどのクレームと紐づけられるか(v2.1.312の`oidc.user_id_claim`との関係)を公式チェンジログで確認すると理解が深まる。
