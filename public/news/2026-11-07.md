## 【GitHub】cloudflare/security-audit-skill — コーディングエージェントを多段階セキュリティ監査員に変える公式Skill
**日付**: 2026-11-07時点で日間トレンド確認(リポジトリ自体は2026-10-24公開) ｜ **⭐ 総数**: 約63.8k ｜ **今日**: +2,524(日間トレンド) ｜ **言語**: 不明(Languages欄非表示、検証スクリプトはNode.js) ｜ **最終更新**: 不明

security-audit-skillは、CloudflareがMITライセンスで公開する「コーディングエージェント向けセキュリティ監査Skill」。SKILL.mdを起点に、①アーキテクチャと信頼境界を`architecture.md`/`coverage-ledger.json`にマッピングする偵察フェーズ、②ledger単位に孤立したハンター群を割り当てるカバレッジ主導のハンティング、③別エージェントが各候補の反証を試みる検証、④`confirmed`/`needs_validation`/`rejected`に分けてスキーマ検証済みの`findings.json`へ書き出す構造化出力、⑤最終的な根拠claimを別エージェントが再チェックする独立検証、⑥`REPORT.md`等のレポーティング、という6フェーズで監査を進める。CloudflareはこのSkillが自社の脆弱性検出ハーネスの"種"になったと説明しており、同じリポジトリへの複数回実行は累積的で、著者らのテストでは1回の実行は複数回実行で見つかる脆弱性の約半分しか見つけられなかったという。

### 話題の理由 / 注目度の根拠
公開から2週間ほどで★63.8k・本日も日間トレンド上位(+2,524)という急成長ぶりが最大の注目点。大手CDN/セキュリティ企業自身がAIエージェントによる脆弱性診断を「Skillとして無償公開」した点、かつ検証担当と発見担当のエージェントを分離する設計思想が、AIエージェントのセキュリティ領域への応用例として広く参照されているとみられる。

### 対象読者
自社リポジトリにAIによる一次セキュリティレビューを組み込みたいセキュリティエンジニア・DevSecOpsチーム。ツール/プロセス両方の実在するエージェント間検証パターンに興味があるAIエンジニア。

### 今日試せること
```sh
npx skills add https://github.com/cloudflare/security-audit-skill --skill security-audit
# --global を付けるとユーザー全体にインストール
```
ツール/サンドボックス(外部通信遮断・環境変数サニタイズ・リソース制限)がない場合、発見内容は`needs_validation`止まりで対象コードは実行されない。

### 深掘りポイント
`validate-findings.cjs`と`validate-coverage-ledger.cjs`という依存ゼロのNode.js検証スクリプトが、実際どこまで「機械判定可能な脆弱性」をカバーしているか(≒誤検知・誤判定の境界)は、同梱のテストファイルと合わせて読む価値がある。

## 【GitHub】thedotmack/claude-mem — SQLite+ChromaでAIエージェントに永続記憶を持たせるツール
**日付**: 2026-11-07時点で週間トレンド確認 ｜ **⭐ 総数**: 約114.0k ｜ **今日(週間)**: +9,318(今回確認した週間トレンド中最大の伸び) ｜ **言語**: TypeScript(README記載) ｜ **最終更新**: 不明(3,975 commits on main)

claude-memは「Claude Code向けに構築された永続記憶圧縮システム」と説明されるツールで、SessionStart/UserPromptSubmit/PreToolUse/PostToolUse/Stop/SessionEndの各ライフサイクルフックでエージェントのツール利用を捕捉し、要約を生成して次回以降のセッションに文脈として渡す。Bunで動くローカルHTTP APIのワーカーサービスと、セッション・観測・要約を保存しFTS5全文検索に対応したSQLite、さらにハイブリッドなセマンティック/キーワード検索を担うChromaベクトルDBを組み合わせる。検索は`mem-search`SkillとMCPツール3種(`search`/`timeline`/`get_observations`)による3層構造で、フィルタ済みIDにのみ詳細を取りに行くことで約10倍のトークン節約を実現すると主張している。Claude Code以外にOpenClaw・Codex・Gemini・Copilot・OpenCodeへの対応も記載されている。

### 話題の理由 / 注目度の根拠
週間+9,318★と、今回確認した主要リポジトリの中で最大の伸び。長時間/複数セッションにわたる文脈の分断という、コーディングエージェント利用者の多くが実感している課題に直接応える実装であることが支持の背景とみられる。

### 対象読者
Claude Code等を日常的に使い、セッションをまたいだコンテキストの引き継ぎ・トークン消費の削減に関心がある開発者。

### 今日試せること
```sh
# Claude Code(プラグイン対応版、Node.js 20+が必要)
/plugin marketplace add thedotmack/claude-mem
/plugin install claude-mem
# 再起動後、前回セッションの文脈が新しいセッションに自動的に現れる

# 代替: npx claude-mem install --ide <IDE名>
```

### 深掘りポイント
`npm install -g claude-mem`だけではSDK/ライブラリのみが入り、プラグインのフック登録は行われない点、`<private>`タグによる保存除外の挙動、`~/.claude-mem/settings.json`でのモード切り替え(`CLAUDE_MEM_MODE`)は、実運用前に確認する価値がある。

## 【GitHub】anthropics/claude-code — v2.1.319でパーミッション待ちの自動拒否・MCPタスクのバックグラウンド化を追加
**日付**: 2026-11-06公開(v2.1.319) ｜ **⭐ 総数**: 不明(リリースページのみ確認、リポジトリトップは未取得) ｜ **今日**: 不明 ｜ **言語**: TypeScript/JavaScript(既知) ｜ **最終更新**: 2026-11-06

Claude Codeの最新リリースv2.1.319では、`permissions.denyInsteadOfPrompting`設定が追加され、通常ならパーミッションプロンプトで待機するツール呼び出しを自動的に拒否してターンを継続させられるようになった。あわせて、ターミナルセッションでのMCPタスクが自動的にバックグラウンド実行に移行する変更が入り(`CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND`で従来の待機動作に戻せる)、フラグ取得だけを止める`CLAUDE_CODE_DISABLE_FEATURE_FLAGS`、`/claude-api latency-optimize`コマンド、`/tasks`への「このセッションの前の部分」行の追加、LLMゲートウェイ経由時などテレメトリ/フィーチャーフラグが無効な場合のautoモードの動作変更も含まれる。

### 話題の理由 / 注目度の根拠
CI/CDやヘッドレス実行でエージェントを自動運用する際に「許可プロンプト待ちで止まる」ことが課題になりやすく、`denyInsteadOfPrompting`はその具体的な解決策にあたる。MCPタスクの自動バックグラウンド化もターミナル利用時の体感速度に直結する変更であり、自動化・無人運用を進めるユーザーにとって実務的な意味が大きい。

### 対象読者
Claude CodeをCI/CDやヘッドレスモードで自動運用しているエンジニア、MCPサーバーを多用するターミナルユーザー。

### 今日試せること
```json
// settings.json
{
  "permissions": {
    "denyInsteadOfPrompting": true
  }
}
```
```sh
# MCPタスクのバックグラウンド化を無効化して従来通り待機させたい場合
export CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND=1
```

### 深掘りポイント
`denyInsteadOfPrompting`はツール呼び出しを「拒否」する設定であり「許可」ではないため、既存のpermissionsルールとどう組み合わさるか(許可リストにあるツールへの影響がないか)を、自分のsettings.jsonで小さく試して確認する価値がある。

[リリースノート](https://github.com/anthropics/claude-code/releases)
