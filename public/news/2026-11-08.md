## 【GitHub】vercel-labs/agent-browser — AIエージェント専用に作られたRust製ブラウザ操作CLI
**日付**: 2026-11-08時点でGitHub Trending(daily)1位 ｜ **⭐ 総数**: 約46.8k ｜ **今日**: +180 ｜ **言語**: Rust ｜ **最終更新**: 不明(GitHub UI上のコミット日時表示を取得できず)

agent-browserは、Vercel LabsがRustで開発したAIエージェント向けブラウザ自動化CLI。`snapshot`コマンドがページを`@e1`のような参照(ref)付きのコンパクトなテキストに変換し、エージェントはそのrefを指定して`click`/`fill`などを実行、結果を再度`snapshot`で確認するというシンプルなループで動く。`--session`ごとにバックグラウンドデーモンがChrome DevTools Protocol経由でブラウザを制御し、Chrome for TestingのほかLightpanda/Obscuraエンジン、iOS Simulator上のMobile Safari、Browserbase等のクラウドブラウザにも対応する。`agent-browser mcp`でMCPサーバーとしてstdio起動できるほか、`npx skills add vercel-labs/agent-browser`でAgent Skillとしても導入できる。

### 話題の理由 / 注目度の根拠
GitHub Trending daily 1位、当日+180★。ブラウザ操作系のエージェントツールは数多いが、Vercel Labs公式かつRust製・MCP対応という組み合わせが「次世代のagentic browser automation」として注目されている。

### 対象読者
Webアプリのテスト自動化やスクレイピング、リサーチ系エージェントを構築しているエンジニアで、ヘッドレスブラウザ操作をエージェントのツール呼び出しに組み込みたい人。

### 今日試せること
```sh
npx agent-browser open example.com
agent-browser snapshot -i
agent-browser click @e1
agent-browser mcp   # MCPサーバーとして起動
```

### 深掘りポイント
認証情報の保管庫・ドメイン許可リスト・アクションポリシーといったセキュリティ機能のドキュメントを読むと、エージェントに実ブラウザを触らせる際のガードレール設計の参考になる。

[リポジトリ](https://github.com/vercel-labs/agent-browser)

mattpocock/skillsは、TypeScript教育者として知られるMatt Pocockが「バイブコーディングではなく実務のエンジニアリング」のために日々使っているAgent Skillsを、自身の`.agents`ディレクトリからそのまま公開したMITライセンスのリポジトリ。スキルは「意図のずれ」「冗長な出力」「動かないコード」「スパゲッティ化した設計」というエージェント開発の4つの失敗パターンに対応する形で設計されており、`/grill-me`(認識合わせの逆質問)、`/tdd`(赤-緑-リファクタのフィードバックループ)、`/to-spec`・`/improve-codebase-architecture`(設計の見直し)などをUser-invoked/Model-invokedに分類して提供する。Claude Code・Codex・GitHub Copilot・Gemini CLI・Cursor・opencode・devin・windsurf・amp・piなど幅広いエージェントに対応し、`npx skills@latest add mattpocock/skills -a <agent>`で導入できる。

### 話題の理由 / 注目度の根拠

### 今日試せること

## 【GitHub】ranxianglei/billion-context — 長期セッションのコンテキストを圧縮するプロキシ型プラグイン
**日付**: 2026-11-08時点でGitHub Trending(daily)14位 ｜ **⭐ 総数**: 約4,600(4.6k) ｜ **今日**: +185 ｜ **言語**: 不明(Languages欄のデータ非表示、tsconfig等からTypeScriptの可能性) ｜ **最終更新**: 不明(GitHub UI上のコミット日時表示を取得できず)

billion-context(bili)は、Claude Code・Codex・OpenCode・Gemini CLI・Aider・GitHub Copilot CLIなど多数のエージェントクライアントとモデルAPIの間に入り、数十億トークン規模の長期セッションを100K程度の小さなコンテキストウィンドウで動かすことを狙うプロキシ型プラグイン。`acp-kernel`でリクエストを圧縮し、モデル自身がコンテキスト増大時に呼び出せる`compress`/`decompress`/`search_context`/`acp_status`の4ツールを注入する。導入はネイティブプラグイン(`bili plugin install <client>`)、ランチャー(`bili <client>`)、baseURLに`/bili/`を付けるURL変更方式の3種類がある。README自身が「Early」「実モデルでの統合テストが次の目標」と明記している点には留意が必要。

### 話題の理由 / 注目度の根拠
当日+185★でトレンド入り。長期エージェントセッションのコンテキスト管理は実務上の悩みが大きい領域で、ContextBenchで-58.3%、LongMemEval-Sで-71.1%のコスト削減という第三者ベンチマーク結果を謳っている点が関心を集めている。

### 対象読者
エージェントに長時間・大規模なタスクを任せており、コンテキストウィンドウの圧迫やAPIコストに悩んでいる開発者。ただし早期段階のツールである点は留意。

### 今日試せること
```sh
npm install -g billion-context --prefix=~/.local
bili claude   # ランチャー方式でClaude Codeを起動
curl -s http://localhost:8787/__bili/health
```

### 深掘りポイント
管理エンドポイントに認証がなく`--host 0.0.0.0`公開は非推奨と明記されている点、および圧縮が「段階的・可逆的・プレフィックスキャッシュを壊しにくい」とする設計根拠を、ベンチマーク論文と合わせて読むと評価しやすい。

[リポジトリ](https://github.com/ranxianglei/billion-context)
