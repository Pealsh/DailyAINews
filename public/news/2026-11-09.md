## 【GitHub】thedotmack/claude-mem — コーディングエージェントにセッション間の記憶を持たせるMCPツール
**日付**: 2026-11-09時点のGitHub Trending(weekly)で確認 ｜ **⭐ 総数**: 約114.9k ｜ **今週**: +7,482(週間トレンド、今週最大の伸び) ｜ **言語**: TypeScript ｜ **最終更新**: 不明(4,049コミット、日時表示なし)

claude-memは、Claude Code/Codex/Cursor/OpenCode等のコーディングエージェントに永続的な記憶を持たせるツール。フックでセッション中の全ツール呼び出し(読み取り・編集・コマンド実行)を捕捉し、「observer」エージェントが短い観察記録とセッション終了時のサマリーを生成する。新しいセッションでは関連する観察記録のコンパクトな索引だけを渡し、詳細は必要なときに`search`→`timeline`→`get_observations`という3種のMCPツールで段階的に取得する「progressive disclosure」方式。保存はSQLite(FTS5によるキーワード検索)とChroma(セマンティック検索)の併用で、クラウド同期はオプトイン。索引ヒットは約50〜100トークン、フル観察記録は約500〜1,000トークンとして「約10倍のトークン節約」を謳うが、これはベンダー側の主張であり独立検証は示されていない。

### 話題の理由 / 注目度の根拠
「エージェントがセッションをまたぐと記憶を失う」という広く共有された不満に直接応える設計で、週間+7,482という今週最大の伸びを記録。

### 対象読者
大規模・継続的なコードベースでClaude Code/Codex/Cursorを日常的に使うエンジニア。

### 今日試せること
```sh
npx claude-mem install
# 既存リポジトリへの導入後
/learn-codebase
```
README によれば`/learn-codebase`は既存リポジトリの前提知識を事前に読み込ませる用途(所要約5分)。

### 深掘りポイント
`search`/`timeline`/`get_observations`の3段構成が素朴なRAGとどう違うか。なおREADME末尾では関連の暗号資産トークン(CMEM)にも触れているが、これは技術的主張ではなくベンダーのマーケティング文脈。

[リポジトリ](https://github.com/thedotmack/claude-mem)

## 【GitHub】vercel-labs/agent-browser — AIエージェント向けに作られたネイティブブラウザ操作CLI
**日付**: 2026-11-09時点のGitHub Trending(daily/weekly)で確認 ｜ **⭐ 総数**: 約47.5k ｜ **今日**: +812(日間トレンド) ｜ **今週**: +1,476(週間トレンド) ｜ **言語**: Rust ｜ **最終更新**: 不明(818コミット、日時表示なし)

agent-browserは、Vercel Labsが公開するRust製のネイティブCLIで、AIエージェントによるブラウザ操作専用に設計されている。使い方は1コマンド1ステップが基本で、`open`でページを開き、`snapshot -i`でページをコンパクトなアクセシビリティツリーのテキスト(`@e1`のような要素参照付き)として取得し、`click @e1`や`fill`など参照ベースの操作でクリック・入力を行う。Chrome DevTools Protocol経由でブラウザを保持するデーモンが`--session`ごとに立ち上がり、ヘッドレスセッションは1時間アイドルで自動終了する。対象が非表示・無効・被覆されている場合は黒く失敗する(偽の成功を返さない)設計で、エージェントにまず読み込ませる「skills」(`agent-browser skills get core`)も同梱、`agent-browser mcp`でMCPサーバーとしても動作する。CSS/テキスト/XPath/セマンティックセレクタ、スクリーンショット/PDF/録画、ネットワーク・クッキー・ストレージの検査、Browserbase等のクラウドブラウザにも対応。

### 話題の理由 / 注目度の根拠
エージェントがWebページを操作する際の「重いAPIではなくテキストベースの簡潔な界面」という具体的ニーズに応える設計で、Apache 2.0・Vercel Labs発という点も注目を後押ししている。

### 対象読者
テスト自動化・Webスクレイピング・Webタスク自動化などで、エージェントに実ページを操作させたいエンジニア。

### 今日試せること
```sh
npm install -g agent-browser
agent-browser install
agent-browser open example.com
agent-browser snapshot -i
```

### 深掘りポイント
ナビゲーションやDOM変化で要素参照が無効化される「refの失効モデル」と、`agent-browser mcp`によるstdio MCPサーバー化の仕組み。

[リポジトリ](https://github.com/vercel-labs/agent-browser)

## 【GitHub】Nutlope/hallmark — AIが作った「いかにもAI生成」な見た目を検出・修正するSkill
**日付**: 2026-11-09時点のGitHub Trending(weekly)で確認 ｜ **⭐ 総数**: 約50.9k ｜ **今週**: +6,624(週間トレンド) ｜ **言語**: CSS(Trendingページ表示) ｜ **最終更新**: 不明(341コミット、日時表示なし) ｜ **ライセンス**: MIT

hallmarkは、Together AI発のSkillで、AIコーディングエージェントが作るWebページから「いかにもAI生成」な見た目を取り除くことを目的とする。見出し上のeyebrowラベル、見出し中の1語だけ色を変える装飾、空枠レイアウト、ページ最下部のニュースレター登録フォーム、偽の成功表示など、具体的な「AIのクセ」を名指しでチェック対象にする。動作フローは、まず既存プロジェクトのフォント・配色・フレームワークを読み取り、実データ(写真・コピー・数値)を一度だけ質問して捏造しないようにし、`scripts/theme.mjs deal`が内蔵50テーマから3つを提案、`draw`が用途(予約/ショップ/ニュースレター等)に応じたページ構成を選ぶ。ヒーローセクションだけを先にビルド・レビューし、`scripts/sloplint.mjs --render`が8段階の画面幅を実ブラウザでレンダリングして検証、その後別コンテキストのサブエージェントが再レビューする。チェックはFloor(コントラスト・フォーカス状態・reduced motion・事実の捏造・モバイル崩れなどのハードブロッカー)、Reflex(AIのクセのデフォルト、理由を記録すれば上書き可)、Finish(仕上げの質)の3段階。`/hallmark redesign <path>`は既存のリンク・フォーム・ハンドラを保持したまま再デザインし`sloplint --before/--kept`で検証、`/hallmark audit <path>`はレポートのみ。Claude Code/Codex CLI/Cursor/OpenCodeに対応。

### 話題の理由 / 注目度の根拠
AIコーディングツールを使う誰もが抱く「これAIが作った感が出てるな」という不満を具体的なチェック項目として言語化し、プロンプトでの指示ではなくlint/audit可能なツールに落とし込んだ点が週間+6,624という伸びにつながっている。

### 対象読者
AIエージェントでフロントエンド・LPを量産しており、テンプレっぽさを避けたいエンジニア。

### 今日試せること
```sh
npx skills add nutlope/hallmark -g
# Claude Code内で、既存ページに対して
/hallmark audit <既存ページのパス>
```

### 深掘りポイント
内蔵50テーマ(素材・タイポグラフィ・配色・表面の定義と参考画像)の内容、および`sloplint --before/--kept`による「ロスレス再デザイン」の仕組み。

[リポジトリ](https://github.com/Nutlope/hallmark)

## 【AI機能】GitHub Copilot Fusion / Copilot Projects — GitHub Universe 2026での発表
**日付**: 2026-10-28〜29開催のGitHub Universe 2026で発表(直近で注目度が高いトピックとして収録。github.blog原文へは本セッションのネットワーク制限で直接アクセスできず、The Next Web/InfoWorld/Digg等の複数の二次報道に基づく)

GitHub Universe 2026の基調講演で、マルチモデルのオーケストレーション機能「Copilot Fusion」がGA(一般提供)、リポジトリを横断して複数エージェントを自律運用する「Copilot Projects」がパブリックプレビューとして発表された。Copilot Fusionは「仮想モデル」として選択でき、リクエストごとに最適と判断したモデルへ自動でルーティングする仕組み。Copilot Projectsは、ゴールと対象リポジトリ群を与えると、ゴール達成に必要な数のエージェントを自動的に起動して走らせる。GitHubは2026年9月時点でエージェントが開始したプルリクエストの比率が40%超(3月の17%から増加)になったと発表したと複数の報道が伝えている。

### 対応製品/機能/制約
- Copilot Fusion: GA。マルチモデルルーティングによる「仮想モデル」として利用。
- Copilot Projects: パブリックプレビュー。複数リポジトリをまとめてコンテキストに追加し、エージェントをゴール志向で走らせる。
- Satya Nadellaの発言として「フロンティア級の品質を保ちつつ40%高速・最大77%低コスト」という数値が複数メディアで報じられているが、GitHub公式発表文での裏付けは本セッションでは未確認(数値は不明瞭/未検証として扱う)。
- Enterprise契約では追加サブスクリプションなしで全Copilot機能が使えるようになった一方、AIクレジットの課金は別途発生する。

### 話題の理由 / 注目度の根拠
GitHubの年次イベントでの発表であり、"エージェントが40%超のPRを開始している"という自社データとともに、マルチモデル運用とマルチエージェント運用の両方を同時に打ち出した点が複数メディアで取り上げられている。

### 対象読者
GitHub Copilotを組織導入している、またはこれから導入を検討するエンジニアリングマネージャー・プラットフォームチーム。

### 今日試せること
Copilot Fusion/Projectsは発表時点でGA/プレビューの対象プランに依存するため、自社のCopilot契約画面で機能が有効化されているか確認し、小さめのリポジトリ群でCopilot Projectsのゴール設定を試すのがよい。

### 深掘りポイント
「仮想モデル」としてのルーティング基準(コスト・速度・品質のトレードオフをどう判定しているか)と、Copilot Projectsにおける複数エージェントの衝突・統合の扱い。GitHub公式ブログ原文(本セッションでは直接確認不能)を後日確認する価値がある。
