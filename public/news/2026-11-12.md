## 【GitHub】openai/codex-security — Codexにセキュリティ監査・パッチ提案までやらせるCLI/SDK
**日付**: 2026-11-12時点のGitHub Trending(daily)で確認 ｜ **⭐ 総数**: 約11,655(Trendingページ表示) ｜ **今日**: +20(Trendingページ表示) ｜ **言語**: TypeScript(Trendingページ表示) ｜ **最終更新**: 2026-11-11(ローカルクローンの`git log`で確認) ｜ **ライセンス**: Apache-2.0

OpenAIが公開するcodex-securityは、Codexの中からセキュリティ監査ワークフローを呼び出せるプラグインと、ターミナルから使えるCLI/SDK(`@openai/codex-security`、コマンド`cs`)の両方を提供する。`cs scan .`でリポジトリ全体・特定パス・Gitの差分だけを対象にスキャンでき、見つかった候補の検証・パッチ生成・既存修正の確認まで一気通貫でこなす。指摘はLinear/Jira/GitHubと連携したりSARIF/JSON/CSVでエクスポートでき、GitHub Actionsでの週次自動スキャンやDocker Composeを使った複数リポジトリの一括(バルク)スキャンにも対応する。OpenAI/Amazon Bedrock/OpenRouter/Fireworks AI/Cheaper Inferenceなど複数のモデルプロバイダーを切り替えて使える点も特徴。

### 話題の理由 / 注目度の根拠
本日時点のGitHub Trending(daily)入り。OpenAI自身がセキュリティ監査を「エージェントのスキル」として製品化し、CLI・SDK・GitHub Action・Dockerまで一式で公開した点、ソースの最終更新がほぼ即日(2026-11-11)である開発速度が注目を集めている。

### 対象読者
Codexを使ってセキュリティレビューを自動化したいセキュリティ/プラットフォームチーム。CIにSARIF/JSON出力の脆弱性スキャンを組み込みたい開発者。

### 今日試せること
```sh
npm install --global @openai/codex-security
cs login
cs scan .                      # カレントリポジトリをスキャン
cs scan . --diff origin/main   # 差分だけスキャン
```
CIで試す場合は`CODEX_SECURITY_API_KEY`をリポジトリシークレットに登録し、`github-action/examples/repository.yml`を`.github/workflows/`にコピーする。

### 深掘りポイント
`AGENTS.md`に書かれた「推測で冗長なredaction処理を足さない」「公開CLIサーフェスを勝手に増やさない」といった開発方針は、セキュリティツール自体の信頼性をどう担保しているかの実例として読む価値がある。Bedrock/OpenRouter等、複数プロバイダーへの対応がどこまで機能差なく動くかも注目点。

[リポジトリ](https://github.com/openai/codex-security)

## 【GitHub】shadcn/improve — 高性能モデルに監査・計画だけさせ、実装は安いモデルに任せるAgent Skill
**日付**: 2026-11-12時点のGitHub Trending(daily)で確認 ｜ **⭐ 総数**: 約10,785(Trendingページ表示) ｜ **今日**: +333(Trendingページ表示) ｜ **言語**: 不明(Trendingページに言語表示なし、構成は`SKILL.md`中心のMarkdown) ｜ **最終更新**: 2026-09-12(リポジトリの`git log`で確認。コード自体は約2か月前から更新なし) ｜ **ライセンス**: MIT

shadcn(shadcn/uiの作者)が公開するimproveは、「理解・判断・仕様化」は高性能で高価なモデルにやらせ、「実装」は安いモデルに渡すという経済合理性を前提にしたAgent Skill。`/improve`を実行するとコードベースを調査し、correctness/security/performance/test coverage/tech debt/dependencies/DX/docs/directionの9カテゴリで並列サブエージェントに監査させた上で、指摘を自分で再読込・検証(サブエージェントは過剰報告しがちという前提)してから優先度表を提示する。選んだ指摘ごとに`plans/`以下へ「実行者が一切の前提知識なしに実行できる」自己完結プランを書き出し、`execute`を使えば安いモデルをisolated worktreeで走らせて差分をレビューまでできる。スキル自体はソースコードを一切書き換えない設計を明言している。

### 話題の理由 / 注目度の根拠
shadcn/uiの作者自身が「モデルの使い分け」という経済設計をSkillの形で公開した点、`npx skills add`一発でAgent Skills対応エージェントに導入できる手軽さから、公開から日間+333という伸びを見せている。

### 対象読者
Claude Code/Codex等のコーディングエージェントで、高価なモデルのレビュー結果を安いモデルに実装させてコストを抑えたいチーム・個人開発者。

### 今日試せること
```sh
npx skills add shadcn/improve
# エージェント内で
/improve quick          # 安く済ませる場合
/improve security       # セキュリティだけ監査
/improve execute 001    # 選んだプランを安いモデルに実行させてレビュー
```

### 深掘りポイント
`references/audit-playbook.md`の9カテゴリの監査観点や、「by-design」な挙動(例: `https_proxy`環境変数をSSRFと誤検知しない)をどう除外しているかという「Vet」フェーズの設計、`--issues`フラグでGitHub Issueとして指摘を公開する際の確認フロー(公開リポジトリなら必ず警告・確認を挟む)は、監査系Skillを自作する際の参考になる。

## 【AI機能】Claude Code v2.1.321/v2.1.322 — 新モデル「Claude Fable 5.2」とVertex高速モード拡大
**日付**: 公式changelog(code.claude.com/docs/en/changelog)より ｜ **v2.1.321**: 2026-11-09 ｜ **v2.1.322**: 2026-11-10

v2.1.321でClaude Fable 5.2(`claude-fable-5-2`)が追加され、Fableモデル系列の既定モデルになった。コンテキストは1M、価格は入力$8/出力$40 per Mtok(キャッシュ読み取り$0.20/Mtok)。既存のFable 5.1の保存済みモデル選択は`fable`という名前に退避される。同リリースでは`claude remote-control`に`--settings <file>`オプションが追加され、ヘッドレスセッションが`.claude/skills`配下のファイル変更を検知して自動的にmods(拡張)を再読み込みするようになった(`CLAUDE_CODE_PLUGIN_DIR_WATCH=0`で無効化可能)。翌v2.1.322ではVertex AI(global/us/euリージョン)向けのfast modeが追加され、Vertex側がfast modeを拒否した場合は自動的に標準速度へフォールバックする。

### 対応製品/機能/制約
- 対応製品: Claude Code CLI(v2.1.321以降)。Fable 5.2はClaude Code内のFableモデルピッカーから選択
- 必要環境: Vertex高速モードはVertex AI経由でClaude Codeを利用している場合のみ対象(global/us/euリージョン)
- 制約: Fable 5.2はFableモデル系列内の切り替えであり、主力のOpus/Sonnetモデルとは別軸。Vertex fast modeはVertex側が拒否すると標準速度に自動フォールバックするため常時高速とは限らない

### 話題の理由 / 注目度の根拠
1Mコンテキスト・比較的安価な価格設定の新モデルを即座に「既定のFableモデル」へ切り替えた点と、クラウド事業者(Vertex)をまたいだ高速化対応を毎日のように小刻みにリリースしている開発速度が、継続的な注目点になっている。

### 対象読者
Claude CodeをVertex AI経由で運用している企業ユーザー、Fableモデル(軽量・高速用途)を使い分けている開発者。

### 今日試せること
```sh
claude update   # 最新バージョンに更新
/model          # Fable 5.2を含むモデルピッカーを確認
```
Vertex AI経由の利用であれば追加設定なしで高速モードが有効になり、Vertex側が拒否した場合のみ自動的に標準速度に戻る。

### 深掘りポイント
`.claude/skills`配下のファイル変更をヘッドレスセッションが自動検知して再読み込みする挙動が、本番運用中のSkill更新にどう影響するか(`CLAUDE_CODE_PLUGIN_DIR_WATCH`で制御可能)。Fable系列モデルがOpus/Sonnetとどう使い分けられる想定か、価格体系から読み取れる位置づけも確認したい。
