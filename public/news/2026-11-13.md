## 【GitHub】GoogleChrome/modern-web-guidance-src — コーディングエージェントに「今のWeb標準」を教え込むAgent Skill
**日付**: 2026-11-13時点のGitHub Trending(daily)で確認 ｜ **⭐ 総数**: 2,772(Trendingページ表示) ｜ **今日**: +799(Trendingページ表示) ｜ **言語**: TypeScript ｜ **最終更新**: 2026-11-12(リポジトリのcommitsページで確認) ｜ **ライセンス**: Apache-2.0

Chrome・Edge・Firefox・MDNの各チームが共同で運営する「Modern Web Guidance」の開発元リポジトリ。コーディングエージェントは学習データに古いWeb実装が大量に含まれているため、ブラウザが既にネイティブ対応している処理を重いJavaScriptで書いてしまいがちという問題に対し、250のWeb機能・203の実例をカバーする専門家監修ガイドをAgent Skillとして提供する。`.agents/skills`配下のSkillはオフライン埋め込みモデル+BM25検索でガイドを引き当て、ネットワーク呼び出しやAPIキーなしでエージェントの文脈に差し込む設計。CSS/HTML/JS/フォーム/パフォーマンス/アクセシビリティ/セキュリティ/組み込みAI/PWA/WebAssemblyなど幅広い領域を扱う。

### 話題の理由 / 注目度の根拠
本日のGitHub Trending(daily)で日間+799という伸び。Chrome/Edge/Firefox/MDNという競合ブラウザベンダーが共同で「エージェント向けWeb知識」を標準化しようとしている点、2026-11-12付けの直近コミットで41ルール・37ガイドにまたがるlegacy-scanルールが追加されるなど開発が活発な点が注目を集めている。

### 対象読者
Claude Code/Codex等のコーディングエージェントでフロントエンド実装をさせている開発者。レガシーなpolyfillやjQuery的実装をエージェントに書かせたくないチーム。

### 今日試せること
```sh
npx modern-web-guidance@latest install
# エージェント内で
# search "<query>" でガイドを検索
# retrieve "<guide-id>" で特定ガイドを取得
# legacy-scan . でコードベースのレガシーパターンを検出
```

### 深掘りポイント
README曰く「evalを使ってモデルが既に知っている内容は意図的に削った」という、Skillの中身を肥大化させないためのキュレーション方針。Origin TrialsやWebMCPなど実験的機能のガイドは`set-allow-origin-trials`等のオプトインフラグを立てないと取得できない設計も、Skillの安全側に倒す作り方の参考になる。

## 【GitHub】QwenLM/qwen-code — マルチプロトコル対応のオープンソースAIコーディングエージェント
**日付**: 2026-11-13時点のGitHub Trending(daily)で確認 ｜ **⭐ 総数**: 29,760(Trendingページ表示、リポジトリページでは29.8k) ｜ **今日**: +151(Trendingページ表示) ｜ **言語**: TypeScript(リポジトリのトピック表示より) ｜ **最終更新**: 2026-11-12(リポジトリのcommitsページで確認) ｜ **ライセンス**: Apache-2.0

AlibabaのQwenチームが開発する、ターミナルに常駐するオープンソースAIコーディングエージェント。GoogleのGemini CLI(v0.8.2)からフォークして独自に発展させてきたプロジェクトで、1.0 PreviewではQoderのエージェントハーネス機能を統合した。OpenAI/Anthropic/Gemini/Qwenの各APIに加えOllama/vLLM経由のローカルモデルにも対応し、実行時にプロバイダーを切り替えられる。SubAgents・Auto-Memory・MCP・Agent Teams・Hooks・Plan Mode・LSP統合といったエージェント機能を備え、ターミナルだけでなくデスクトップアプリ・Web UI・VS Code/Zed/JetBrainsのIDEプラグイン・Telegram/DingTalk等のチャット連携からも使える。SWE-bench Verifiedで直近7バージョン平均76.4〜77.8%のスコアを報告している。

### 話題の理由 / 注目度の根拠
本日のGitHub Trending(daily)で日間+151、総スター29,760。マルチベンダー(OpenAI/Anthropic/Gemini/Qwen)・マルチインターフェース(CLI/デスクトップ/Web/IDE/チャット)に対応した汎用コーディングエージェントとして、特定ベンダーにロックインされたくない開発者からの支持を集めている。

### 対象読者
複数のLLMプロバイダーやローカルモデルを切り替えながらコーディングエージェントを使いたい開発者。CI/CDにヘッドレスモードでエージェントを組み込みたいチーム。

### 今日試せること
```sh
npm install -g @qwen-code/qwen-code@latest   # Node.js 22+が必要
qwen            # プロジェクトディレクトリで対話セッションを開始
qwen -p "..."   # ヘッドレスモード(CI/CD・バッチ向け)
qwen serve --open   # 実験的Web UIを起動
```

### 深掘りポイント
`qwen daemon`モードはループバックで認証なしに待ち受けるため、共有ホストで使う場合は`QWEN_SERVER_TOKEN`と`--require-auth`の設定が必須とREADMEが明記している。Gemini CLIからのフォークという出自を踏まえ、本家Gemini CLIや他のオープンソースエージェント(OpenCode等)とのSkill/MCP互換性がどこまであるかも確認したい点。

## 【AI機能】Self-hosted Claude Managed Agents — Managed Agentsサービスそのものを自社インフラで運用できる新オプション
**日付**: 2026-11-12、Anthropic公式ドキュメント(platform.claude.com)のリリースノートで確認

Claude Managed Agentsは、自前でエージェントループやツール実行基盤を作らずにClaudeを自律エージェントとして動かせるマネージドサービス。従来はサンドボックス(ツール実行環境)だけを自社インフラに置く「self-hosted sandboxes」が選べたが、今回追加された「self-hosted Claude Managed Agents」はサービス本体(API・エージェントループ・エージェント/セッション/履歴の保存)まで自社インフラで完結できるようにする。サーバー(`cma-server`)とワーカー(`ant beta:worker`コマンドまたはSDK worker)を自社で立て、PostgreSQL 16以降のデータベースに状態を保存する。モデル呼び出し先はAnthropic(デフォルト)のほか、Amazon Bedrock・Google Cloud(Anthropic managed)・Microsoft Foundry・自前のモデルゲートウェイから選べる。

### 対応製品/機能/制約
- 対応製品: Claude Managed Agents(ベータ、`managed-agents-2026-04-01`ベータヘッダー必須)。利用にはAnthropicアカウントチームへの申請が必要
- 対応モデル: Claude Fable/Mythos 5.2系列を含む全モデル(モデル自体はAnthropic側またはBedrock/Google Cloud/Microsoft Foundry経由で実行)
- 必要環境: サーバー・DB(PostgreSQL 16+)・サンドボックス用ワーカーを自社で構築・運用・各リリースごとに自分でインストールする必要がある。コンソールやAdmin CLI(`cma-server-admin`、Linux x86-64/Arm、macOS Apple silicon)も同梱
- 制約: ホスト型サービス(Anthropic運用)にしかない機能もあるため事前確認が必要。bashツールはワーカープロセスの権限そのままの実シェルであり、分離は自分で用意するコンテナ/VM(Docker Compose scaffoldや`cma-sandboxes`のHelm chart)に委ねられる。Zero Data Retention(ZDR)は通常のManaged Agentsでは非対応だが、self-hosted版は自分でデータを保持する前提でZDR適用除外(対象)になる

### 話題の理由 / 注目度の根拠
エージェントの状態(セッション履歴・ファイル)をどこに置くかという、エンタープライズ導入のコンプライアンス/データレジデンシー要件に直接応える機能。モデル推論先をBedrock/Google Cloud/Microsoft Foundry/自前ゲートウェイから選べる「ベンダーロックインしないマネージドエージェント基盤」という設計が注目点。

### 対象読者
規制業界やデータレジデンシー要件からAnthropicのクラウドにエージェントの状態を置けない企業。複数クラウド/オンプレ環境でエージェント基盤を自社管理したいプラットフォームチーム。

### 今日試せること
一般提供ではなくAnthropicアカウントチームへの申請制のため、今日すぐ試せるのは次のステップ。
```text
1. Anthropicアカウントチームにself-hosted Claude Managed Agentsへのアクセスを申請
2. ダウンロード許可後、各リリース同梱の operator-guide.md をClaude Code等に読み込ませて構成を相談
3. ant beta:worker でワーカーを起動し、cma-server-admin で環境(environment)とそのキーを作成
```

### 深掘りポイント
「サーバーはエージェントのシェル/ファイルツールを直接実行しない」設計(実行は必ずワーカー側)と、信頼境界ごとに別デプロイが必要という「マルチテナンシー」の注意書きは、自社でこの基盤を運用する際のセキュリティ境界設計の参考になる。通常のManaged AgentsがZDR非対応な理由(セッションが状態を持つリソースのため)と、self-hostedだけがその制約を外せる理由の違いも押さえておきたい。
