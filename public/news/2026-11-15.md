## 【GitHub】JuliusBrussee/caveman — 「原人語」でエージェントのトークンを削るAgent Skill+プロキシ
**日付**: 2026-11-15時点のGitHub Trending(daily)で確認 ｜ **⭐ 総数**: 120,017(リポジトリページ実測) ｜ **今日**: +227(Trendingページ表示) ｜ **言語**: Go(Trendingページ表示。TypeScript製CLI/プラグイン類も同梱) ｜ **コミット数**: 2,042 ｜ **ライセンス**: Apache-2.0(MITライセンスファイルも同梱)

2026年4月に「冗談」として公開されたClaude Code向けSkillが、10万スターを超える規模に成長した。中核は「Say less(原人語で簡潔に答える)」「Read less(ログ/JSON/CSV/YAML/テスト出力を読み込む前に圧縮する)」の2本柱で、新機能として「Auto(タスクごとにモデルと推論強度を自動選択)」「Blocks(エージェントが書いたスクリプトをリポジトリに保存し再利用するコードモード)」を4.0で追加した。Adobe Researchの論文「CAVEWOMAN」(8モデル・5データセットで1.4〜2.4倍のコスト削減を追試)、JetBrainsの86タスクA/B検証(p=0.82で品質差なし、出力トークン8.5%減)、Elastic(Elasticsearch Labsで8つのMCPシナリオを再現し応答トークン63.6%減)という3件の社外検証結果をREADMEで公開している点が特徴。Skillのみ(プロキシなし)で試すこともできる。

### 話題の理由 / 注目度の根拠
GitHub Trending(daily)で本日+227、総スター120,017・フォーク7,000。リポジトリのREADME内に「Hacker News #1、904ポイント」「GitHub Trending #1(2026年7月)」という自己申告の実績が記載されている(いずれも今回の確認時点ではなく過去のピーク時の数値で、本セッションでは一次ソース=リポジトリREADME上の記載としてのみ確認できた)。「トークン削減系Skill」という実務直結のテーマに加え、効果を外部研究機関3件が追試・引用している点が単なるバズを超えた注目理由になっている。

### 対象読者
Claude Code/Codex/Gemini CLI/OpenCode等でAPIコスト・トークン消費を気にしているチーム。ログやテスト出力の読み込みでコンテキストを圧迫されがちな大規模リポジトリの開発者。

### 今日試せること

## 【GitHub】Tencent/LoopForge — 複数のコーディングエージェントCLIをSOPと承認ゲートで統制する自社ホスト型オーケストレーター
**日付**: 2026-11-15時点のGitHub Trending(daily)で確認 ｜ **⭐ 総数**: 862(リポジトリページ実測) ｜ **今日**: +101(Trendingページ表示) ｜ **言語**: Go(Trendingページ表示) ｜ **コミット数**: 324 ｜ **ライセンス**: MIT

Tencent製の自社ホスト型プラットフォーム。チャットでMain Botに依頼するとDockerサンドボックス内でリポジトリをチェックアウトし、役割(Role=プロンプト+実行エージェント+モデル+Skills+MCPツールの組)に作業を委任してPRを作成する。繰り返し使う進め方は「SOP」(Agent/Script/Human-gate/Sub-SOPの各ノードから成るワークフロー)として保存し、次回以降は同じ承認フローで実行できる。対応CLIはCodeBuddy・Codex・Claude Code・OpenCode・Cursor CLI・Antigravity・Kimi Code・Pi・DeepSeek Harness・ZCodeの10種。サーバーを立てずにCLIへ直接組み込む軽量版「LoopForge Local」も用意されている。

### 話題の理由 / 注目度の根拠
GitHub Trending(daily)で本日+101。「エージェントに丸投げするとレビューやテストを飛ばして止まっても気づかれない」という、単体のコーディングエージェント運用で実務チームが直面する課題に対して、役割分離・人間承認ゲート・実行履歴の可観測性をセットで提供する設計が評価されている。Dify/n8n/Flowiseのような汎用ワークフローツールとの違いをFAQで明示している点も実務者の関心に刺さっている。

### 対象読者
複数人・複数リポジトリでコーディングエージェントを運用し始めたが、品質や承認プロセスが個々のエージェント実行任せになっているチーム。社内インフラ上でAIコーディングの実行履歴・コストを管理したい組織。

### 今日試せること
```sh
git clone https://github.com/Tencent/LoopForge.git
cd LoopForge
./start.sh        # Docker/Compose/Python/curlを自動チェックして起動
# APIキー不要のデモSOP(スクリプト+承認ゲートのみ)から試せる
```
サーバーを立てずに1リポジトリだけ試す場合:
```sh
npx -y loopforge-cli@latest install claude
# Claude Code内で
/start-devflow "<やりたいこと>"
```

### 深掘りポイント
README内の「A delivery we actually ran」(4つのCodeBuddy役割が実際にPythonの修正を計画・実装・レビュー・要約した実例と検証記録へのリンク)を読むと、SOPが実際にどこまで自動化され、どこで人間承認が挟まるかの粒度が具体的に分かる。

## 【AI機能】Claude Code v2.1.325 — スケジュールタスク/`/loop`がSkillを無断実行しないための確認フロー
**公開日**: 2026-11-13 ｜ **対応製品**: Claude Code

公式changelog(code.claude.com/docs/en/changelog)によると、v2.1.325では「スケジュールタスクと`/loop`が、`allowed-tools`やhooksを宣言したSkillを実行する前に確認を挟むようになった」という変更が加わった。無人実行を許可するには`permissions.allow`に`Skill(name)`を明示的に追加する必要がある。合わせて、サンドボックス化されたBashコマンドが通常の権限フローに従うようになった点(`sandbox.autoAllowBashIfSandboxed: true`で従来動作に戻せる)、MCPバンドル(`.mcpb`/`.dxt`)がプラグインディレクトリ配下に展開されるようになった点も含まれる。

### 話題の理由 / 注目度の根拠
Agent Skillsが`allowed-tools`やhooksという強い権限を持てる以上、無人実行(スケジュールタスクや`/loop`)の文脈でそれを暗黙に許可してしまうのはセキュリティ上のリスクになる。今回の変更は「Skillの配布が広がるほど、無人実行時の権限確認が重要になる」という、Agent Skills全体のエコシステムが直面している課題への具体的な対応例になっている。

### 対象読者
Claude Codeのスケジュールタスクや`/loop`を使って無人運用しているユーザー。サードパーティ製Skillを導入しているチーム。

### 今日試せること
```sh
# 無人実行で特定Skillを許可リストに追加
# .claude/settings.json の permissions.allow に追記
"permissions": { "allow": ["Skill(my-skill-name)"] }
```

### 深掘りポイント
公式changelogの同バージョンの項目には、プラグインの`plugin.json`に`engines["claude-code"]`でサポート対象バージョン範囲を指定できる変更も含まれている。Skill配布・プラグイン配布の双方で「対応バージョンの明示」と「無人実行時の確認」が同時期に強化された経緯を合わせて見ると、Agent Skills普及に伴う運用面の整備の方向性が見える。
