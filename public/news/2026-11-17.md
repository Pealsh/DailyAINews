## 【GitHub】ag-ui-protocol/ag-ui — エージェントとアプリをつなぐイベントベースのオープンプロトコル
**日付**: 2026-11-17確認(GitHub Trending daily) ｜ **⭐ 総数**: 18,878 ｜ **今日**: +790(Trendingページ表示) ｜ **言語**: TypeScript ｜ **最終更新**: 2026-11-16(直近コミット「Merge pull request #3412 ...enable-coderabbit-ag-ui」、`git clone`で確認) ｜ **ライセンス**: MIT(LICENSEファイルで確認)

CopilotKitが開発するAG-UIは、AIエージェントとユーザー向けアプリケーションを繋ぐための軽量・イベントベースのオープンプロトコル。エージェントはトークンストリーミング、途中でのツール呼び出し、状態の共有、人間の承認待ち、サブエージェントの生成など、単純なリクエスト/レスポンスに収まらない動作をするため、従来は各フレームワークが独自に配線していた。AG-UIはそれを単一の双方向イベントストリーム(31イベント型・8ファミリー)に置き換え、同じエージェントをWeb・モバイル・ターミナル・Slackのどのクライアントからでも動かせるようにする。1.0でJSON Schemaに基づく安定仕様が確定し、TypeScript/Python/.NET SDKはその仕様から生成される。LangChain、CrewAI、Google ADK、Microsoft Agent Framework、AWS Strands、Claude Agent SDKなど15以上のフレームワークに統合済みで、Google・Microsoft・Amazon・Oracleが採用していると明記されている。MCP(ツール/コンテキストをエージェントに与える)、A2A(エージェント間通信)と並ぶ「エージェントをユーザーに届ける」役割を担う3つ目の標準という位置づけ。

### 話題の理由 / 注目度の根拠
GitHub Trending(daily)で本日+790、総⭐18,878。MCP・A2Aが先行して定着した一方、「エージェントをどうユーザー向けアプリに繋ぐか」は各社が独自実装していた領域で、そこを標準化するプロトコルの1.0安定版が出たことが伸びの背景にある。

### 対象読者
複数のエージェントフレームワークを使い分ける開発者、チャットUI/ジェネレーティブUIを自作しているフロントエンド開発者、既存のエージェントに人間承認待ちやサブエージェント表示を追加したいチーム。

または30行のサーバー/クライアント例を自分で動かす場合:

## 【GitHub】backnotprop/plannotator — エージェントの計画・コードレビューに人間の注釈を挟むローカルレビュー層
**日付**: 2026-11-17確認(GitHub Trending daily) ｜ **⭐ 総数**: 12,492 ｜ **今日**: +689(Trendingページ表示) ｜ **言語**: TypeScript ｜ **最終更新**: 2026-11-16(直近コミット「Merge pull request #3557 ...fix/inbox-remote-markdown-images-links」、`git clone`で確認) ｜ **ライセンス**: Apache-2.0 または MIT のデュアルライセンス(LICENSE-APACHE/LICENSE-MITで確認)

Plannotatorは、Claude Code・Codex・Copilot CLI・Gemini CLI・OpenCode・Kiro・Droid・Ampなど主要コーディングエージェントに対し、計画(plan)・コード変更・HTMLなどの出力をブラウザ上で注釈・レビューし、フィードバックをそのままエージェントのセッションに送り返すローカルレビュー層。核となる「Plan Review」は各ハーネスのフック(Claude CodeならExitPlanModeのPermissionRequestフック)に食い込み、エージェントが計画を提示した瞬間に自動でレビューUIを開く。「Code Review」は`/plannotator-review`でgit diffやGitHub/GitLabのPR/MRをそのまま差分ビューアに読み込み、大きな変更はエージェントが章立てして見せる「Guided Review」も使える。新機能の「Plannotator Inbox」は複数エージェントからの質問・提案を1つのローカル受信箱にまとめ、セッションを止めずに後から返信できる設計。配布バイナリはSHA256・SLSA provenance・CycloneDX SBOM付き。

### 話題の理由 / 注目度の根拠
GitHub Trending(daily)で本日+689、総⭐12,492。マルチエージェント運用が広がる中で「エージェントの提案にいつ・どう人間が介入するか」というレビュー層を、特定ハーネスに依存せず横断的に提供している点が評価されている。

### 対象読者
複数のコーディングエージェントCLIを横断的に使う開発者、計画承認やPRレビューをエージェント任せにせず人間が目を通したいチーム。

### 今日試せること
```sh
curl -fsSL https://plannotator.ai/install.sh | bash
# Claude Codeの場合はさらに
/plugin marketplace add backnotprop/plannotator
/plugin install plannotator@plannotator
```
インストール後、エージェントに何か計画を立てさせると、ブラウザで注釈レビューが自動的に開く。

### 深掘りポイント
リモート/SSH/devcontainer環境での`PLANNOTATOR_REMOTE`・ポート転送設定を確認し、ローカルGUIが使えないクラウド開発環境でチームがどう導入できるかを検証する。

[リポジトリ](https://github.com/backnotprop/plannotator)

## 【Simon Willison】"A quote from Prompting Claude Fable 5.2" — プロンプトで「コードの所有者」を明示すると重複コード統合率が上がる
**日付**: 2026-11-10 ｜ **媒体**: simonwillison.net

Simon Willisonは、Anthropicの公式ガイド「Prompting Claude Fable 5.2」から、プロンプトに「このコードの所有者は誰か」を明示する一文を加えるとFable 5.2が重複コードを統合する頻度が大きく変わる、という一節を引用している。Anthropicが社内の小規模タスクで検証した結果では、所有者を明示しない場合は1割未満だった統合率が、所有者を明示する一文を加えるだけで約5割まで上がったと報告されている。Willison自身はこの数字をそのまま一般化せず、タスクによって差があるという留保付きで紹介している点も合わせて触れている。

### 話題の理由 / 注目度の根拠
モデル自体の切り替えやファインチューニングではなく「プロンプトの一文」だけでエージェントの挙動(コード重複の解消率)が数倍変わるという具体的な数値を伴う指摘であり、プロンプトエンジニアリングの実務知として注目されている。

### 深掘りポイント
