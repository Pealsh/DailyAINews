## 【GitHub】mvanhorn/last30days-skill — Reddit・X・HN等を横断調査しエンゲージメントで順位付けするAgent Skill
**日付**: 2026-11-18確認(GitHub Trending daily) ｜ **⭐ 総数**: 68,956(Trendingページ表示) ｜ **今日**: +772(Trendingページ表示) ｜ **言語**: Python ｜ **最終更新**: 2026-11-17(`git clone`で確認、直近コミットは「fix(watchlist): preserve budget accounting after topic removal」) ｜ **ライセンス**: MIT

任意のトピックについて過去30日間のReddit・X・YouTube・TikTok・Hacker News・Polymarket・GitHub・Web上の反応を横断的に収集し、1つのブリーフにまとめるAI Agent Skill。README上で「編集部の掲載順ではなく、upvotes・いいね・出来高といったエンゲージメントで結果を順位付けする」ことを明言しているのが特徴。`skills/last30days/SKILL.md`がコマンド仕様の正本(source of truth)で、本体エンジン`last30days.py`、macOSキーチェーン連携の`setup-keychain.sh`、ウォッチリスト管理`watchlist.py`等のスクリプトを束ねる。Reddit・Hacker News・Polymarket・GitHubは認証不要で使え、X・YouTube・Perplexity等は環境変数のAPIキーがあれば追加で使える、という段階的な構成。Claude Code・Codex・Cursor・Gemini CLI・Grok Build CLIなど50以上のホストにAgent Skills標準(`npx skills add`)で導入できる。

### 話題の理由 / 注目度の根拠
本日のGitHub Trending(daily)で+772、総68,956⭐。本ブリーフが毎日やろうとしている「複数プラットフォームを横断してその日の話題を拾う」作業そのものをAgent Skillとして定型化した実例で、Agent Skillsの実務応用として分かりやすい。

### 対象読者
市場・プロダクト動向のモニタリングを自動化したいPM・マーケター、Claude Code等でSkillsを使い始めたい開発者。

### 今日試せること
```sh
npx skills add mvanhorn/last30days-skill
# Claude Codeの場合
/plugin marketplace add mvanhorn/last30days-skill
```
導入後は「last30days AIコーディングエージェントのニュース」のように自然文で呼び出せる。APIキーなしでもReddit・HN・Polymarket・GitHubだけで動作する。

### 深掘りポイント
`skills/last30days/SKILL.md`の`allowed-tools`(Bash, Read, Write, AskUserQuestion, WebSearch)を読み、自作のリサーチ系Skillでどこまでツール権限を絞るべきかの参考にする。

## 【GitHub】obra/superpowers — 「設計→計画→サブエージェント実装→レビュー」を自動で踏ませるAgent Skills群
**日付**: 2026-11-18確認(GitHub Trending daily) ｜ **⭐ 総数**: 319,262(Trendingページ表示) ｜ **今日**: +598(Trendingページ表示) ｜ **言語**: Shell(スクリプト構成の多数派、`git clone`後の拡張子集計で確認) ｜ **最終更新**: 2026-11-03(`git clone`で確認、直近リリースはv7.0.2) ｜ **ライセンス**: MIT

Superpowersは、コーディングエージェント向けの「複数の合成可能なSkillと、それを確実に使わせる初期指示」からなる開発手法。起動直後にすぐコードを書き始めるのではなく、まず要件を聞き出し、短く読める単位で設計案を提示して承認を取り、承認後に実装計画を作成、そのあとは`subagent-driven-development`によってサブエージェントが各タスクを実装・レビューしながら進めるという一連の流れを自動化する。同梱スキルは`brainstorming`・`writing-plans`・`executing-plans`・`requesting-code-review`・`receiving-code-review`・`verification-before-completion`・`dispatching-parallel-agents`・`writing-skills`など多数。真のRed/Green TDD・YAGNI・DRYを徹底させる設計で、スキルは自動的にトリガーされるため利用者側の明示的な呼び出しは基本不要。Claude Code・Cursor・Codex・Gemini CLI・OpenCode・Devin CLIなど15以上のホストに対応する。

### 話題の理由 / 注目度の根拠
本日のGitHub Trending(daily)で+598、総319,262⭐という圧倒的な規模。「Agent Skillsを束ねてチーム開発プロセスそのものを標準化する」という方向性の先駆けで、addyosmani/agent-skills等の後発プロジェクトが比較対象として挙げる基準点になっている。

### 対象読者
AIエージェントに数時間単位の自律実装を任せたい開発者、設計・計画・レビューの規律をプロンプトではなくスキルとして固定化したいチーム。

### 今日試せること
```sh
# Claude Code公式マーケットプレイスから
/plugin marketplace add superpowers
/plugin install superpowers
```
導入後、新機能の実装を依頼すると自動的に`brainstorming`スキルが起動し、要件確認から始まる。

### 深掘りポイント
`skills/subagent-driven-development/SKILL.md`と`implementer-prompt.md`を読み、サブエージェントへの実装委任とレビューのプロンプト設計を自作のマルチエージェントワークフローに転用できるか検討する。

[リポジトリ](https://github.com/obra/superpowers)

## 【GitHub】google-research/paper-orchestra — 実験ログから投稿可能なLaTeX論文を書き上げるマルチエージェント・フレームワーク
**日付**: 2026-11-18確認(GitHub Trending daily) ｜ **⭐ 総数**: 2,879(Trendingページ表示) ｜ **今日**: +1,175(Trendingページ表示) ｜ **言語**: Python(リポジトリのCLI構成・`requirements.txt`より) ｜ **最終更新**: 2026-11-15(`git clone`で確認、直近コミットは不正なエスケープシーケンス修正のPRマージ) ｜ **ライセンス**: Apache-2.0

PaperOrchestraは、未整理の研究アイデアや実験ログといった「raw materials」を入力に、投稿先カンファレンスのLaTeXテンプレート(例: CVPR2025)に沿った完成度の高い論文原稿を自動生成するマルチエージェント・フレームワーク。アウトライン生成・関連研究の検索と統合・各セクションの執筆・内容の推敲という役割分担されたエージェントが順に処理し、`--use_plotting`を指定すると図表生成エージェントも加わる(デフォルトは無効)。Writer/文献調査エージェントとReflection(推敲)エージェントはそれぞれ使うLLMを個別に設定できる。Streamlit製のインタラクティブデモも`frontend`ディレクトリに同梱している。README上は「Googleの公式サポート製品ではない」と明記されたリサーチコードという位置づけ。

### 話題の理由 / 注目度の根拠
本日のGitHub Trending(daily)で+1,175、総2,879⭐とまだ小規模だが伸び率が高い。「コーディング支援」ではなく「論文を書くマルチエージェント」という応用先の新しさと、Google Researchが公開した点が注目されている。

### 対象読者
実験ログや断片的なメモから論文の初稿を素早く作りたい研究者、マルチエージェントのタスク分割(アウトライン/文献調査/執筆/推敲)の設計例を探している開発者。

### 今日試せること
```sh
git clone https://github.com/google-research/paper-orchestra.git
cd paper-orchestra && pip install -r requirements.txt
python paper_writing_cli.py \
  --raw_materials_dir /path/to/raw_materials/ \
  --latex_template_dir /path/to/latex_template/ \
  --output_dir /path/to/output/
```

### 深掘りポイント
`autoraters`ディレクトリ(自動評価用エージェント)の実装を読み、生成した論文原稿の品質をどのように自動採点しているかを確認すると、LLM-as-judge的な評価設計の参考になる。

[リポジトリ](https://github.com/google-research/paper-orchestra)

## 【GitHub】GoogleChrome/modern-web-guidance-src — 「レガシーなパターン」からコーディングエージェントを引き離すAgent Skill
**日付**: 2026-11-18確認(GitHub Trending weekly) ｜ **⭐ 総数**: 8,410(Trendingページ表示) ｜ **今週**: +6,542(Trendingページ表示) ｜ **言語**: TypeScript ｜ **最終更新**: 2026-11-17(`git clone`で確認、直近コミットは「publish: drop the next channel; publish latest only」) ｜ **ライセンス**: Apache-2.0

Modern Web Guidanceは、LLMの学習データに古いWebパターンが大量に含まれているせいでコーディングエージェントが非効率なJavaScriptを生成してしまう問題に対し、モダンなブラウザAPI・パフォーマンス/アクセシビリティ上の推奨実装・軽量なフォールバックをエージェントのコンテキストに直接差し込むCLI兼Agent Skill。オフラインの埋め込みモデルとBM25検索でクエリに最適なガイドをローカル完結(ネットワーク通信・APIキー不要)で検索し、該当ガイドをコード例・落とし穴・フォールバックつきで取得する。262種のモダンWeb機能と204種の実使用例を収録し、`legacy-scan`コマンドで既存コードベースをスキャンして古いパターンを検出することもできる。本リポジトリはそのガイダンスを執筆・検証・評価するソース側。

### 話題の理由 / 注目度の根拠
今週のGitHub Trending(weekly)で+6,542、総8,410⭐。「エージェントが書くコードの質」をモデル側ではなくAgent Skill側のナレッジ注入で改善するアプローチで、Google Chromeチームの公式ツールという裏付けもあり注目されている。

### 対象読者
フロントエンド開発でコーディングエージェントに古いパターン(不要なポリフィル、冗長なJS等)を書かせてしまい困っている開発者、モダンなWeb APIの知見をエージェントに持たせたいチーム。

### 今日試せること
```sh
npx modern-web-guidance@latest install
npx modern-web-guidance@latest search "animate a dialog modal backdrop"
npx modern-web-guidance@latest legacy-scan .
```

### 深掘りポイント
`legacy-scan`を自分のリポジトリで実行してどのレガシーパターンが検出されるかを確認した上で、`skills-src`配下のガイド執筆フォーマットを読み、自社のコーディング規約を同じ形式でエージェントに注入できないか検討する。

[リポジトリ](https://github.com/GoogleChrome/modern-web-guidance-src)

Astryxは、Meta社内で8年間育てられ13,000以上のアプリを支えてきたデザインシステムをオープンソース化したもの。150以上のアクセシブルなコンポーネント、ブランド単位のテーマ設定、ダークモード、既成テンプレート、CLIを備える。内部的にはStyleXを使い、React 19以降向けの型付きReactコンポーネントとして配布される。テーマはCSSカスタムプロパティの上書きで差し替えられ、`swizzle`コマンドでコンポーネントのソースをまるごと自分のプロジェクトにコピーして改変することもできる。READMEは「人と、その人と一緒に働くAIエージェントの両方のために」設計されているとしており、エージェントがUIを生成・改変する際に迷わないコンポーネント構造・命名を意識した設計という位置づけ。現在ベータ版。

### 話題の理由 / 注目度の根拠
