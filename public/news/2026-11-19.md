## 【AI機能】Claude Code「Code Review」— GitHub PRを4段階パイプラインで検証付き自動レビュー
**日付**: 2026-11-19確認(code.claude.com公式ドキュメント) ｜ **対応プラン**: Team・Enterprise(個人向けのローカル`/code-review`は全プランで利用可) ｜ **対応コードホスト**: GitHub(GitHub Enterprise Server/Cloudのデータレジデンシー含む)

GitHub上のプルリクエストを、Anthropicの管理基盤上で「検出(複数エージェントが並行して差分と周辺コードを読む)→検証(候補の指摘をコードと照合して誤検知を除去)→ランク付け(重複除去・重大度順)→投稿(インラインコメント+サマリ+チェック実行)」という4段階で自動レビューする機能。レビューはPRを承認・ブロックせず、マージ判断は常にチーム側に残る。デフォルトでは本番を壊すバグなど「正しさ」に焦点を当て、フォーマットやテスト不足は対象外だが、リポジトリに`REVIEW.md`を置くことで観点を調整できる。レビューの深さは組織単位またはリポジトリ単位でQuick(最速・最安)/Standard(既定)/Deep(最も丹念・最も高コスト)から選べ、PRオープン時・毎プッシュ時・リクエスト時(`@claude review`コメント)のいずれで走らせるかも設定できる。

### 話題の理由 / 注目度の根拠
GitHub PRレビューを「人間が最初に読む前にAIが先に読む」設計へ切り替える具体的な実装で、Anthropic自身がClaude Codeチーム内のレビュー体制見直し(2026年10月の公式ブログで言及)を経て一般提供した機能という位置づけ。11月18日にはAnthropic主催のウェビナーでも同テーマが取り上げられている。

### 対象読者
GitHub上でチーム開発しているTeam/Enterprise契約の開発チーム、AIレビューとCIをどう組み合わせるか検討しているエンジニアリングマネージャー。

### 今日試せること
```sh
# プランに関わらず、ローカルで軽量版を試す
claude
> /code-review
```
Team/Enterprise契約があれば、OwnerがClaude GitHub Appを導入し、リポジトリごとにレビュー深度(Quick/Standard/Deep)と実行タイミングを設定することで本番運用できる。

### 深掘りポイント
`/code-review`(ローカル・全プラン)、Code Review(Team/Enterprise・GitHub App常駐)、Ultrareview(クラウドサンドボックス)、GitHub Actions上でのCI実行、という4つの「レビューの入手経路」の違いを比較し、自分のチームにどれが合うかを検討する。

[ドキュメント](https://code.claude.com/docs/en/code-review)
