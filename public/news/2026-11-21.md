## 【GitHub】HKUDS/CLI-Anything — ワンコマンドで任意のGUIソフトを「エージェント対応CLI」に変換するAgent Skill/プラグイン
**日付**: 2026-11-21確認(GitHub Trending daily) ｜ **⭐ 総数**: 61,324(Trendingページ表示) ｜ **今日**: +774(Trendingページ表示) ｜ **言語**: Python ｜ **最終更新**: 2026-09-22(`git clone --depth 1`で確認、直近コミットは「Merge pull request #481 from HKUDS/chaohuang-ai-patch-6」) ｜ **ライセンス**: Apache 2.0(`git clone`後のLICENSEで確認)

GIMP、Blender、Inkscape、Audacity、LibreOffice、OBS Studio、Kdenliveなど実在する70種類超のソフト向けにすでに生成済みのCLIを、コミュニティ製のcli-hubからワンコマンドでインストールできるほか、`/cli-anything <ソフトのパスまたはリポジトリURL>`で未対応ソフトに対しても「分析→設計→実装→テスト計画→テスト実装→ドキュメント→SKILL.md生成→公開」の8フェーズを自動実行し、REPLモード・JSON出力・undo/redoを備えたClickベースのCLIを新規生成する。生成物はSKILL.mdとして公開され、Claude Code・OpenClaw・OpenCode・Codex・Qodercli・GitHub Copilot CLIなど主要エージェントから共通インターフェースとして呼び出せる。`/cli-anything:refine`では既存CLIの機能カバレッジのギャップを分析し、非破壊的に段階拡張できる。README記載では1,540件のテストが通過しているとされる(本セッションでの再実行による検証はしていない)。

### 話題の理由 / 注目度の根拠
本日のGitHub Trending(daily)で+774、総61,324⭐。「GUI専用ソフトをエージェントが使えるCLIに変換する」という汎用的な課題にパイプライン全体を自動化して取り組み、既に70種類超の実在ソフトへの適用例(cli-hub)を公開済みという完成度が支持されている。

### 対象読者
GUIしか提供していない自前ツールやレガシーソフトをエージェントから操作したい開発者、社内ツールをAIエージェント対応にしたいプラットフォームチーム。

### 今日試せること
```sh

/plugin marketplace add HKUDS/CLI-Anything
/plugin install cli-anything

# 既存ソフトの完全なCLIを生成(全8フェーズ)

```
cli-hub(https://hkuds.github.io/CLI-Anything/)で、GIMPやBlenderなど既に生成済みのCLIを探してインストールすることもできる。

### 深掘りポイント
`cli-anything-plugin/HARNESS.md`に記載された「分析→設計→実装→テスト計画→テスト実装→ドキュメント→SKILL.md生成→公開」の8フェーズ定義を読むと、LLMエージェントに大きな生成タスクを安定して遂行させるための工程分割の実例として参考になる。

## 【AI機能】Claude Code v2.1.329 — スケジュールタスク・/loopの起床・forkを/tasksに統合、MCP再接続も自動化
**日付**: 2026-11-20確認(anthropics/claude-code 公式CHANGELOG.md、バージョン2.1.329) ｜ **対象**: Claude Code 全プラン(ローカルの`/tasks`・`/mcp`はプラン不問で利用可能)

Claude Codeの`/tasks`に、このセッションのスケジュールタスク・`/loop`の起床・ゴール・このセッション内のforkが一覧表示されるようになり、`x`キーで確認の上1件ずつ停止できるようになった。あわせて、古いプロトコルバージョンのまま再接続が遅延していたHTTP MCPサーバーの大半を、Claude Codeが自動で再接続するよう修正された。リモートHTTP MCPサーバーが接続を拒否した場合、`/mcp`のサーバーページに、そのJSON-RPCエラーメッセージを表示する「Server message」行が追加された。また、Code ModeをOpenTelemetryのイベント・メトリクス収集と併用できるようになり、コードが行う各ツール呼び出しのイベントが送信される(トレーシングは引き続き無効のまま)。

### 話題の理由 / 注目度の根拠
バックグラウンドで動くスケジュールタスクや`/loop`、fork、サブエージェントが増えるほど「今何が動いているか」を把握しにくくなるという課題に対し、`/tasks`への統合という具体的な解決策が示された点、およびMCPサーバーの自動再接続・エラー可視化によって運用上の謎のハングが減ることが注目されている。

### 対象読者
`/loop`やスケジュールタスク、サブエージェントのforkを多用しているユーザー、複数のリモートMCPサーバーを運用しているチーム。

```sh

> /tasks
```
バックグラウンドで動いているスケジュールタスクや`/loop`の起床、forkが一覧表示されるので、不要なものを`x`で止める運用に切り替えてみる。MCPサーバーの接続エラーが気になる場合は`/mcp`でサーバーごとの「Server message」を確認する。
