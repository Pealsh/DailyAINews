## 【GitHub】Tracer-Cloud/opensre — CIの赤を自分で調査し、fix案をPRにpushする自己ホスト型CI/CD信頼性エージェント
**日付**: 2026-11-22確認(GitHub Trending daily、最終コミットは2026-11-22 00:21:37 +0530) ｜ **⭐ 総数**: 13,952(Trendingページ表示) ｜ **今日**: +450(Trendingページ表示) ｜ **言語**: Python ｜ **最終更新**: 2026-11-22(`git clone --depth 1`で確認、直近コミットは「docs: add CloudWatch and EKS pages, note incident use beyond CI/CD (#7081)」) ｜ **ライセンス**: Apache 2.0(`git clone`後のLICENSEで確認)

CIが落ちると「失敗した」ことは分かっても「なぜ」「どう直すか」は分からない、という課題に対し、OpenSREはCLIエージェントとして失敗したCIの実行を読み、ログ・直近のコミットとデプロイ・関連するログ/メトリクス/トレースを取得し、ツール呼び出しのループで仮説検証を行い、CI起因の失敗とコード起因の失敗を切り分けた上でPRブランチにfixをpushしてレビューに回す。自社のインフラ上で自分のモデルを使って動かすセルフホスト設計で、外部LLM呼び出し前に機密識別子をマスクするオプションも備える。CI/CDに限らずEKS・EC2・CloudWatch・Kubernetes・Grafana・Alertmanager・Datadog・Slack・GitHubと連携し、本番インシデントの調査やアラートのルーティング先としても使える。Publicアルファ段階。

### 話題の理由 / 注目度の根拠
本日のGitHub Trending(daily)で+450、総13,952⭐。「AIが書くコードは増えても、それをCIで検証し続ける作業は人手に残る」という具体的な痛点に対し、調査から修正PRの作成までを自動化する完成度の高いエージェントを示した点が支持されている。

### 対象読者
不安定なCIの再実行・原因調査に時間を取られているチーム、本番インシデント対応にAIエージェントを組み込みたいSRE/プラットフォームエンジニア。

### 今日試せること
```sh
# macOS/Linux
curl -fsSL https://install.opensre.com | bash -s -- -gh
opensre
```
インストール後、Gitリポジトリのあるターミナルで`opensre`を起動し、失敗したCIの調査からfix提案までの一連の流れをまず自分のプロジェクトで試すのが早い。

### 深掘りポイント
`AGENTS.md`に記載されている、旧来のgraph/chainフレームワーク層を取り除いた後の現行のコード主体なエージェントアーキテクチャの説明を読むと、ツール呼び出しループを安定させるための構成上の判断が分かる。

## 【GitHub】mjmirza/app-store-compliance — 12種のAIコーディングツールにskillとして入り込み、submit前にApp Store/Google Playのリジェクト要因を検出するプレイブック
**日付**: 2026-11-22確認(GitHub Trending daily) ｜ **⭐ 総数**: 3,336(Trendingページ表示) ｜ **今日**: +724(Trendingページ表示) ｜ **言語**: Shell ｜ **最終更新**: 2026-11-15(`git clone --depth 1`で確認、直近コミットは「chore: release 2.4.0 with the November gap sweep checks (#2320)」) ｜ **ライセンス**: OpenRoots Agent License 2.3(`git clone`後のLICENSEで確認。一般的なOSSライセンスではなくAgent向けの独自ライセンス)

iOSアプリの約4件に1件がリジェクトされ、Google Playは2025年に175万件超のPlay submissionをブロックしたとされる現状に対し、App StoreとGoogle Playの審査ガイドラインを機械可読なリジェクトパターン集(`data/rejection-patterns.json`)として体系化し、プロジェクトをスキャンして重大度順のfix計画を出すプレイブック。`agent-os/hooks/app-store-compliance-guard.sh`を直接実行する単発スキャンのほか、`scripts/install.sh --tool <ツール名>`でClaude Code・Codex CLI・Gemini CLI・OpenCode・Cursor・GitHub Copilot・Grok・Qwen Code・Kimi Code・Factory Droid・Augment Auggie・Windsurfの計12ツールにhookとskill(Claude Codeでは`/app-store-audit`)を組み込み、submitコマンドの直前にガードを自動実行して重大なリジェクトリスクがあれば止める。EU AI Act・DMA、COPPAや各国の年齢確認規制など2026年時点の地域別法規制もdocs配下に別立てで用意されている。

### 話題の理由 / 注目度の根拠
本日のGitHub Trending(daily)で+724という大きな伸び。審査リジェクトという具体的かつ高コストな痛点に対し、12種類のAIコーディングツールへのインストーラと、毎回のsubmitを自動でブロックするhook連携まで用意した実務的な完成度が支持されている。

### 対象読者
iOS/Androidアプリをリリースする開発者、AIコーディングエージェントにリリース前チェックを任せたいチーム。

### 今日試せること
```sh
# 単発スキャン(何もインストールしない)
git clone https://github.com/mjmirza/app-store-compliance ~/repositories/app-store-compliance
bash ~/repositories/app-store-compliance/agent-os/hooks/app-store-compliance-guard.sh "/path/to/your/app"

# Claude Codeにhook+skillとして常設する場合
bash ~/repositories/app-store-compliance/scripts/install.sh --tool claude
```

## 【AI機能】Claude Code v2.1.330「easel」— 依頼やMCPメトリクス結果に応じて自動でチャートを描く組み込みmod
**日付**: 2026-11-21確認(anthropics/claude-code 公式CHANGELOG.md、バージョン2.1.330。最終コミットは2026-11-21 20:41:02 UTC) ｜ **対象**: Claude Code Pro・Max、一部Team・Enterprise(macOS/Linux)

Claude Codeに「easel」という組み込みmodが追加され、ユーザーが頼んだときやMCPのメトリクス結果を受け取ったときに、Claudeが自動でチャートを描けるようになった。自動描画が不要な場合は`/config`でオフにできる。同バージョンでは、Enterprise Admin Consoleで管理されている組織へのサインインにも対応し、`claude auth login`後に組織設定とそのクラウドプロバイダ/ゲートウェイを自動適用するようになった。あわせて、長い会話をcompactした直後にClaude Codeが最大数分フリーズする不具合、一部ページでWebFetchが数分フリーズしたり空の結果を返したりする不具合など、安定性に関する修正も多数含まれている。

### 話題の理由 / 注目度の根拠
ツール呼び出しの結果やメトリクスをテキストで読むだけでなく、Claude自身がその場でグラフとして可視化できるようになった点が、エージェントとの対話のUXを変える機能として注目されている。

### 対象読者
MCPサーバーのメトリクスやログを日常的にClaude Codeで確認している開発者、ダッシュボード的な出力をチャットの中で欲しいユーザー。

### 今日試せること
```sh
claude
> このMCPサーバーのメトリクスをグラフにして
```
自動描画を無効化したい場合は`/config`からeaselをオフにする。

### 深掘りポイント
CHANGELOG全文は巨大なため、今回確認したのは前日掲載分からの差分(v2.1.329→v2.1.330)のみ。easelの実装詳細やチャートの描画ロジックはanthropics/claude-codeリポジトリ本体で別途確認が必要。
