## 【GitHub】awslabs/cli-agent-orchestrator — AWS Labs製、13種のAIコーディングCLIをtmuxで束ねるマルチエージェント・オーケストレーター
**日付**: 2026-11-23確認(GitHub Trending python, daily。最終コミットは2026-11-23 08:41:01 +1100) ｜ **⭐ 総数**: 1,634(Trendingページ表示) ｜ **今日**: +11(Trendingページ表示) ｜ **言語**: Python ｜ **最終更新**: 2026-11-23(`git clone --depth 1`で確認。直近コミットは「test: root-fix five flaky tests found by the #1350 measuring window (#1448)」) ｜ **ライセンス**: Apache 2.0(`git clone`後のLICENSEで確認)

CLI Agent Orchestrator(CAO)は、Kiro CLI・Claude Code・Codex CLI・Antigravity CLI・Hermes・Kimi CLI・Qwen Code・MiniMax Code・GitHub Copilot CLI・OpenCode CLI・Oh My Pi・Cursor CLI・Grok Build CLIという13種のAIコーディングCLIを、それぞれ独立したtmuxセッション内でネイティブなプロセスのまま起動し、スーパーバイザー役のエージェントがワーカーへタスクを並列または逐次で委任できるようにするオーケストレーターである。ローカルで動く`cao-server`がセッションを管理し、各ワーカーは自身の認証・権限を保ったまま動く。`cao install code_supervisor`で組み込みのスーパーバイザープロファイルを入れ、`cao launch --agents code_supervisor`で起動、Web UI(`http://localhost:9889`)やtmuxへのアタッチで進行を確認できる。AWS Labs配下のプロジェクトで、開発ドキュメント(`CODEBASE.md`)やskillsディレクトリも整備されている。

### 話題の理由 / 注目度の根拠
本日のGitHub Trending(python, daily)で+11。AWS Labsという組織発でありながら特定のAWSサービスに縛られず、既存のAIコーディングCLI群を「supervisor-worker」のマルチエージェント構成でそのまま協調動作させるという汎用的な設計が、複数ツールを併用する開発者から注目されている。

### 対象読者
複数のAIコーディングCLI(Claude Code、Codex CLI等)を既に使い分けているチーム、supervisor-workerパターンでの並列タスク委任を試したい開発者。

### 今日試せること
```sh
uv tool install git+https://github.com/awslabs/cli-agent-orchestrator.git@main --upgrade
cao install code_supervisor
cao-server &                 # 別ターミナルで起動したままにする
cd /path/to/your/project
cao launch --agents code_supervisor
```
起動後は`http://localhost:9889`のWeb UIか、tmuxにアタッチしてスーパーバイザーがワーカーに作業を割り振る様子を観察できる。

### 深掘りポイント
`skills/`配下の`cao-supervisor-protocols`・`cao-worker-protocols`のSKILL.mdには、非同期の`assign`と同期待ちの`handoff`をどう使い分けるか、ワーカーからのコールバックが届かない場合のデバッグ手順などが具体的に書かれており、マルチエージェントの委任プロトコル設計の実例として読める。
