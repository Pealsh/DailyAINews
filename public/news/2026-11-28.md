## 【AI機能】Skills over MCP — MCPサーバーが自前のスキルを配布できるパブリックベータ
**日付**: 2026-11-24公開ベータ開始 ｜ **提供**: Anthropic（Claude / Claude Code）

MCPサーバーがツール定義と一緒に自分のSKILL.mdを配布できるようになった新機能。Claude Code 2.1.331以降が対応し、必要なタイミングでオンデマンドにスキルを読み込む「progressive disclosure」の仕組みはローカルの`.claude/skills`と同じ。サーバー運営者がスキル内容を更新すれば、利用者は再インストールなしに最新版を使える点が最大の違い。1サーバーあたり最大100スキル、1スキル400KBまでという上限があるとされる（複数の二次情報源による）。利用者は`/skills`メニューで管理でき、`Skill(mcp__<server名>__*)`をdenyに追加することで特定サーバーのスキル読み込みを止められる。Pro/Max/Ultraはデフォルト有効、Teamは組織オーナーがConnectorsで有効化、Enterpriseは「近日対応」とする報道がある一方、ソース間で記載が割れている部分もある。同日、MCPのTasksとElicitationも正式リリースされた。

### 話題の理由 / 注目度の根拠
「Skills vs MCP」という2025年末からの議論（Simon Willisonが「MCPより大きな話かもしれない」と評した経緯）に対し、Anthropicが「両者は別レイヤーで、MCPサーバーがSkillsを配布できる」という統合の答えを公式に出した形。開発者コミュニティ（dev.toなど）でも「MCP vs Agent Skills」の整理記事が複数出ている。

### 対象読者
自社MCPサーバーを配布している開発者、複数のMCPサーバー＋ローカルスキルを併用しているClaude Codeユーザー。

### 今日試せること
Claude Codeを2.1.331以降に更新し、`/skills`でMCPサーバー経由のスキルが表示されるか確認する。社内MCPサーバーを持っている場合は、ツール定義と並べてSKILL.mdを同梱する構成を検討する。

### 深掘りポイント
ローカルスキルとMCP配布スキルの「読み込みモデルが同一」という設計が、既存のSKILL.md作成ノウハウをそのままサーバー側配布に転用できることを意味する。1スキル400KBという上限を踏まえたファイル分割の作法を確認しておきたい。

[関連記事](https://claude.com/blog/skills)

## 【AI機能】Claude Ship — `/ship`一発でPRレビュー・修正・承認を自動化
**日付**: 2026-11-23発表（ベータ） ｜ **提供**: Anthropic（Claude Team / Enterprise、GitHub連携）

プルリクエストをレビュー・修正・マージ判断まで通す新システム。GA済みの「Code Review」（複数の観点からPRを多角的にレビューし、所見を検証・分類してPRに投稿、リポジトリごとにQuick/Standard/Deepを選択可）に加え、ベータの「PR Steward」（CI失敗やコンフリクト、レビュー指摘に自動対応してPRをグリーンに保つ。プッシュごとに変更内容と取り消し方法をコメント。`@claude`で指示、`@claude stop`で停止可能。自分では承認・マージしない）と「Claude Approvals」（リポジトリに置いたポリシーファイルに基づき定型的な変更を自動承認、特定条件では人間の承認を必須化。ブランチ保護に組み込む前にobserve-onlyモードで試すことを推奨）の2エージェントが追加された。GitHub上のリポジトリが対象で、既存のブランチ保護・必須チェックと共存する。Zero Data Retention・HIPAA設定・カスタマー管理鍵を使う組織では利用不可。Enterprise組織は2027年1月15日までに申請すれば最低1万ドルのClaude Ship利用クレジットを獲得できる（獲得後30日以内に使用）。

### 話題の理由 / 注目度の根拠
「エージェントにPRを任せる」というワークフローを、レビュー・修正・承認ポリシーまで含めて公式機能としてパッケージ化した点が大きい。課金もトークン量に応じて変動するため、導入コストの見積もりが論点になっている。

### 対象読者
GitHub上でチーム運用しているエンジニアリングマネージャー、PRレビューの一次対応を自動化したいチームリード。

### 今日試せること
Claude CodeまたはClaude Desktopを更新し、変更に対して`/ship`を実行してPR作成からレビューまでの流れを確認する。管理者は新規リポジトリでまずCode ReviewをQuickレベル・Claude Approvalsをobserve-onlyモードで有効化し、挙動を見てから権限を広げる。

### 深掘りポイント
Claude Approvalsの「承認ポリシーをリポジトリ内のファイルとして書く」設計は、どの変更を自動承認してよいかの判断基準を明文化する良い機会になる。PR Stewardがトークン課金である点も踏まえ、PR量に応じたコスト上限の設定を検討したい。

[関連記事](https://claude.com/resources/articles/introducing-claude-ship)
